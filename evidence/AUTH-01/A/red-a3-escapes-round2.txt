AUTH-01-A / A3 — RED-FIRST รอบสอง: เปลี่ยน "โครง" ของ pin ไม่ใช่ไล่ปิด regex ทีละตัว
=====================================================================================
ที่มา: audit รอบสองของ PR #744 ระบุว่า pin
`apps/backend/__tests__/unit/identity-provider-naming-collision.test.js`
ยังลอดได้ทั้งชุด เพราะรอบแรกแก้ที่ "รูปตัวอักษร" ทีละ mutation ที่ auditor ตั้งชื่อ
รอบนี้จึงเปลี่ยนสามโครง:
  A. เทสต์ 4/5 เปลี่ยนจาก denylist ของค่า provider → allowlist ว่าง
     ("ห้ามเขียน identity_links เลย ไม่ว่า provider จะเป็นค่าอะไร")
  B. normalize ข้อความก่อน match (ยุบ quote สามชนิด + ตัวดำเนินการเขียนทุกรูป
     + API ที่เขียน property โดยไม่มีตัวดำเนินการ) แทนการเพิ่ม alternation
  C. ตาราง field-map ต้อง match เป็น "คู่" (provider_id ↔ 'providerId') ไม่ใช่
     `: 'providerId'` ลอย ๆ ซึ่งเป็นเครื่องผลิต false positive 15 บรรทัด

วิธีเก็บหลักฐาน (Law 3.11 — ต้องเคยแดงจริงก่อนถึงจะเคลมว่าบังคับได้):
  1. เขียนไฟล์ mutation ลงใน SCAN_DIRS (ใช้ apps/backend/shared/ เท่านั้น —
     dispatch ห้ามแตะ services|middleware|controllers|routes|scripts)
  2. รัน pin suite ด้วย **ตัว pin ที่ commit ไว้แล้วที่ 35b9d518** → คาดว่า PASS (= ลอด)
  3. เปลี่ยนโครงของ pin
  4. รัน pin suite ด้วย mutation ตัวเดิม → ต้อง FAIL (= จับได้)
  5. ลบไฟล์ mutation แล้วยืนยัน `git status --porcelain` ว่าง
