# เดินฝั่งเจ้าหน้าที่ด้วยเบราว์เซอร์จริง (2026-09-06)

ผู้ตรวจเอกสาร `วิชัย ตรวจเอกสาร` เข้าระบบด้วยประตูจริงของเจ้าหน้าที่
(เลขประจำตัว 13 หลัก ที่ `/auth/provider/login`) · backend :8099 จากต้นไม้ปัจจุบัน ·
Postgres ใช้แล้วทิ้ง :55450 · สคริปต์: `walk-script.mjs` · ผลย่อ: `walk-output.txt`

**หมายเหตุเรื่อง fixture**: คำขอถูกตั้งเป็น `ASSIGNED_FOR_REVIEW` ตรงในฐานข้อมูล ไม่ได้ยื่น
ผ่านประตูจริง เพราะประตูยื่นยังติด `F-APPV2-01` ซึ่งเป็นเรื่องเงินและรอมติ operator ·
ทุกอย่างหลังจากนั้นเป็นการกดจริงบนหน้าจอจริง

## สิ่งที่ทำงานถูกต้อง

| ขั้น | ผล |
|---|---|
| คิวผู้ตรวจ | คำขอโผล่ใน `pendingReview` เมื่อ workflowState เป็น ASSIGNED_FOR_REVIEW |
| หน้าตรวจเอกสาร | ข้อ 1.1 แสดง 12 ช่องบังคับ + 3 ช่องไม่บังคับ ชื่อไฟล์ที่แนบ และปุ่ม ดู/รับ/ขอเพิ่ม |
| ผลตรวจเบื้องต้น 1.2–1.4 | ขอบข่าย IN · คุณสมบัติ PASS · สรุป INCOMPLETE → **COMPLETE** เมื่อรับครบ |
| แถบตัดสินใจ | "ส่งคำขอเอกสารเพิ่ม" ปิดอยู่เมื่อไม่มีการขอเพิ่ม · "รับคำขอ" เปิดเมื่อครบ |
| กด "รับคำขอ" | `POST /document-decision` → 200 `{action:"ACCEPT_ALL", round:1, status:"DOC_APPROVED", notified:true}` |
| ผลในฐานข้อมูล | คำขอเดินต่อเป็น **PENDING_AUDIT_FEE** · แจ้งเตือน "✅ เอกสารผ่านการตรวจสอบ" ถึงเกษตรกร |

## ช่องโหว่ที่การเดินเปิดโปง และแก้แล้ว

**เจ้าหน้าที่กด "รับเอกสารนี้" กับช่องที่ยังไม่ได้แนบไฟล์ได้ และระบบบันทึกว่า ACCEPTED**

วัดได้: กดรับทุกช่องตามลำดับแล้วฐานข้อมูลมี 14 แถว รวม `water_test` และ `soil_test`
ซึ่งไม่มีไฟล์อยู่เลย · ประตูตรวจแค่ว่า "ช่องนี้อยู่ในคำขอไหม" แล้ว
`if (verdict === 'ACCEPTED') return true;` — ไม่เคยถามว่ามีเอกสารให้ตรวจหรือไม่

ทำไมเป็นเรื่องใหญ่: `ACCEPT_ALL` ปฏิเสธก็ต่อเมื่อยังมีช่อง **บังคับ** ที่ผลตรวจไม่ใช่ ACCEPTED
⇒ รับช่องบังคับที่ว่างเปล่าได้เมื่อไร คำขอก็ผ่านด่านตรวจเอกสารทั้งที่กระดาษไม่เคยมา และ
บันทึกว่า "เจ้าหน้าที่รับแล้ว" สำหรับเอกสารที่ไม่มีตัวตน ยังเป็นร่องรอยเท็จในสายการตรวจสอบ
ตาม ISO/IEC 17065 §7.4

แก้: ประตูปฏิเสธด้วย `REVIEW_SLOT_NOT_ATTACHED` (422, ลงทะเบียนใน error-codes พร้อม
remediation) · หน้าจอปิดปุ่มรับของช่องที่ไม่มีเอกสารพร้อมบอกทางออก ("ให้เลือก ขอเอกสารเพิ่ม")
· "ขอเอกสารเพิ่ม" กับช่องว่างยังทำได้ตามปกติ — นั่นคือกรณีหลักของปุ่มนั้น

พิสูจน์ซ้ำหลังแก้: **กดรับ 12 ช่อง · ข้ามช่องที่ไม่มีเอกสาร 3 ช่อง** และฐานข้อมูลมี 12 แถวพอดี
