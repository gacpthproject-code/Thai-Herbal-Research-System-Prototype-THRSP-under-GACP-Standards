# ส่วนของพนักงาน — กดจริงทุกบทบาทที่เดินถึงได้ (2026-09-06)

เข้าระบบด้วยประตูเจ้าหน้าที่จริง (เลข 13 หลัก) แล้วยิงประตูจริงของแต่ละบทบาท

## ผู้ตรวจเอกสาร (document_reviewer) — เดินครบ ✅

`evidence/officer-walk-2026-09-06/` · คิว → ตรวจรายช่อง → ตัดสิน → แจ้งเตือน →
คำขอเดินต่อเป็น `PENDING_AUDIT_FEE` · เจอและปิดช่องโหว่ "รับเอกสารที่ไม่มีตัวตน"

## ผู้จัดตารางตรวจ (scheduler) — ด่านทั้งสี่ถูกต้อง ✅

แดชบอร์ดตอบ และเห็นคำขอที่พร้อมดำเนินการ · ประตูสร้างนัดตรวจปฏิเสธถูกทุกกรณีที่ลอง:

| ลอง | คำตอบ |
|---|---|
| นัดวันเสาร์ | `400` — "ไม่สามารถนัดหมายในวันหยุดราชการหรือวันเสาร์-อาทิตย์ได้" |
| ONSITE แต่ไม่ระบุสถานที่ | `400` — "mapLink or location is required for ONSITE mode" |
| คำขอยังอยู่ที่ `DOC_FEE_PAID` | `400` — "Application must be in AUDIT_FEE_PAID before scheduling (current: DOC_FEE_PAID)" |
| **ตั้งสถานะเป็น `AUDIT_FEE_PAID` ตรงในฐานข้อมูล แล้วลองใหม่** | `400` — **"Phase 2 payment must be confirmed before scheduling"** |

ข้อสุดท้ายคือด่านที่ดีที่สุดในชุดนี้: **ประตูไม่เชื่อสถานะอย่างเดียว** มันถาม
`isPhase2PaymentConfirmed(app)` คือถามรายการชำระเงินจริง · สถานะเป็นสิ่งที่สคริปต์ซ่อมข้อมูล
ตั้งได้ ส่วนเงินที่เข้าจริงไม่ใช่ ⇒ การป้องกันซ้อนสองชั้นบนเส้นที่ควรซ้อน

## ผู้ตรวจประเมิน (auditor) — แดชบอร์ดตอบ แต่เดินต่อไม่ได้ ⛔

`GET /api/provider/auditor/dashboard` → 200 พร้อมคิวว่างและ KPI ครบรูป

ไปต่อไม่ได้เพราะยังไม่มีนัดตรวจ และนัดตรวจสร้างไม่ได้เพราะ **ยังไม่มีการชำระเงินงวดที่ 2 จริง**
· การสร้างรายการชำระเงินคือการแตะเงิน ซึ่งกฎ L3 ห้าม agent ทำ (อ่าน/แจ้ง/เสนอ diff เท่านั้น)

**นี่คือขอบเขตที่แท้จริงของสิ่งที่เดินได้โดยไม่ต้องรอมติ** — และมันตรงกับ `F-G4-71`:
ไม่มีใครออกใบแจ้งหนี้ของงวดที่ 2 ⇒ ไม่มีการจ่าย ⇒ ไม่มีนัดตรวจ ⇒ ผู้ตรวจประเมินไม่มีงาน
