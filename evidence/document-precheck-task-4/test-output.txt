=== Fix round 1 (task-4-fix-round-1, on top of 9f05bf6b) ===

Fix: extractFromPdf() no longer calls PDFParse in this (Jest-loaded) module.
It forks a child `node` process running the new
services/document-precheck/pdf-extract-worker.js, which does call
getInfo/getText/getScreenshot — as a plain `node <file>` invocation, not
inside Jest's module sandbox. Parent<->child talk over
child_process.fork()'s IPC channel: one {type:'extract'} message in, one
{type:'result'} message out, then the parent kills the child
(`runPdfWorkerChild()`'s `settle()`, called on message/error/exit alike).
extractDocument's own timeout handler also kills the in-flight child
directly (`inFlight.child.kill('SIGKILL')`) alongside terminating any
in-flight tesseract worker, so a timeout tears down both real subprocesses
it could be waiting on. extract.js no longer requires 'pdf-parse' at all —
only pdf-extract-worker.js does. tesseract-service.js's header edit from the
original Task 4 commit is unchanged.

=== Fix round 2 (task-4-review.md, on top of c646bf29) ===

Fixes (see red-output.txt's Fix round 2 section for the matching RED, and
each file's own "Fix round 2" comment for the full reasoning):
  I1 — extract.js: `inFlight.aborted` checked (synchronously, no `await` in
    between the check and the next call) after `readFile`, before `fork`,
    and at the top of `runOcr`; each `extractDocument()` call gets its own
    `new TesseractService()` (tesseract-service.js now also exports the
    class, not only its module-level singleton) instead of sharing one
    worker across calls.
  I2 — tesseract-service.js's `initialize()` now checks both
    `tha.traineddata`/`eng.traineddata` exist BEFORE calling
    `Tesseract.createWorker()`, throwing a clear, fast, catchable error if
    not; `runOcr` in extract.js throws when tesseract reports
    `success:false`, instead of returning `{text:'', confidence:0}`.
    tessdata.js's `TESSERACT_WORKER_OPTIONS` also gained a no-op
    `errorHandler` — needed to stop an UNRELATED crash-on-uncaught-throw
    path in tesseract.js's own worker message loop for a DIFFERENT class of
    rejection (an `action:'load'` reject); it alone did not fix the hang
    (see that file's comment for why both pieces were needed).
  I3 — new pdf-raster-scale.js: `scaleForPage()` picks `getScreenshot`'s
    scale from each page's own MediaBox so the rasterised long side stays
    ≤2500px; pdf-extract-worker.js now sends one IPC message per page
    (`type:'page'`) instead of batching all pages into one final message,
    plus a defensive per-page byte cap.
  Minor 1 — pdf-extract-worker.js exits on `disconnect`.
  Minor 2 — extract.js forks with an explicit minimal `env`
    (`PATH`, `NODE_ENV` only) and `execArgv: ['--max-old-space-size=512']`,
    not the parent's full `process.env`/`process.execArgv`.
  Minor 4 — `isPasswordException` in pdf-extract-worker.js now checks
    `instanceof PasswordException` first, falling back to the `err.name`
    string match only if pdf-parse ever stops exporting that class.
  Minor 5 — new test: a timeoutMs (50ms) chosen so the timer lands while the
    forked child is provably still running (polled via `pgrep -f`), then
    asserts no such process survives.
  Minor 3, 6, 7 — left alone per the coordinator's instruction.
