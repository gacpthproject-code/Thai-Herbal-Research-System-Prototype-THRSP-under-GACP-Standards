# approver-photo-coords-mismatch: หลักฐาน

ปัญหา: แฟ้มผู้อนุมัติพิมพ์พิกัดแปลงที่ยื่นไว้ แต่ทุกภาพถ่ายขึ้นว่า "ฟาร์มไม่มีพิกัดในทะเบียน" และ "ถ่ายนอกช่วงเวลาตรวจ"
เพราะฝั่ง backend อ่านพิกัดจาก `formData.locationData` ขณะที่ wizard หกขั้นเขียนไว้ที่ `formData.farmData`
และหน้าตรวจแปลงส่งเวลาเช็คอินเป็นเวลาถ่ายของทุกภาพ

## เดินประตูจริง (2026-10-29)

ผู้ตรวจพื้นที่ล็อกอินบนจอมือถือ 390×844 (ตั้ง GPS ไว้ห่างแปลงราว 15 เมตร) กดเริ่มตรวจ แล้วอัปโหลดภาพ 5 ภาพผ่านหน้าตรวจแปลงจริง
จากนั้นบันทึกผลผ่านทุกข้อด้วย service เดียวกับที่หน้าเรียก แล้วผู้อนุมัติเปิดแฟ้มบนจอ desktop
ทั้งสองรอบใช้ Postgres ทดสอบตัวเดียวกันและคำขอแบบเดียวกัน คือพิกัดแปลง 13.8621, 100.5144 อยู่ใน `formData.farmData`

- ก่อนแก้ ใช้ origin/main a26fe65cd ใน worktree สะอาดที่มี Prisma client ของตัวเอง
- หลังแก้ ใช้ fix/approver-photo-coords

ข้อที่ต้องรู้:
- ทั้งสองรอบยังมีข้อสังเกต "ภาพซ้ำหรือคล้ายกันมาก" ในภาพที่ 2-5 เพราะภาพทดสอบทั้ง 5 ภาพหน้าตาคล้ายกัน ข้อนี้ไม่เกี่ยวกับการแก้รอบนี้
- บนจอ "ถ่ายเมื่อ" แสดงแค่วันที่ จึงมองไม่เห็นว่าเวลาถ่ายของแต่ละภาพต่างกัน หลักฐานเรื่องเวลาอยู่ในไฟล์ json
- ต้นฉบับเวลาถ่ายยังเป็น `CALLER_SUPPLIED_UNVERIFIED` คือเครื่องผู้ตรวจเป็นคนส่งมา ระบบยังพิสูจน์ไม่ได้ ซึ่งหน้าจอก็เขียนบอกไว้ด้านล่างกล่องภาพ

## รันซ้ำ

`walk/run.sh` เปิด backend กับ next dev ต่อรอบ ทุกตัวเริ่มใน process group ของตัวเอง และสคริปต์ปิดทุก group เมื่อจบหรือถูกหยุด
ต้องมี Postgres ทดสอบที่ 127.0.0.1:55434 ก่อน

```
BEFORE_TREE=<worktree ที่ origin/main ซึ่งมี Prisma client ของตัวเอง> ~/work/state/heavy.sh timeout 5400 bash evidence/approver-photo-coords-mismatch/walk/run.sh
```

log ของการรันวันนี้อยู่ที่ `walk/before-run.log` กับ `walk/after-run.log`
ใน `after-run.log` มีรอบ before ที่ล้มอยู่ด้วย รอบนั้นรันจาก main checkout ที่ Prisma client เก่า จึงตอบ 500 ว่า `Unknown field identitySource` รอบ before ที่ใช้ได้คือ `before-run.log`

เทสต์ RED→GREEN: `red.log`, `green.log`, `redgreen.sh`
