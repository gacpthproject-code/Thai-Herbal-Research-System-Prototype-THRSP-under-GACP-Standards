# ภาคผนวก R10 — บันทึกการปลูกบนมือถือด้วยการสแกน QR ที่แขวนไว้ที่แปลง

> ต่อจาก `docs/superpowers/specs/2026-08-20-planting-tnt-design.md` (R1-R9)
> ที่มา: คำสั่ง operator 2026-08-21 — "เฉพาะระบบมือถือ ระบบบันทึกการปลูก จะต้องสแกนผ่าน QR code ที่ออกไปแขวนไว้ที่แปลง"
> สถานะ: **PENDING** — บันทึกข้อกำหนดแล้ว ยังไม่อนุมัติทางเลือกที่ต้องตัดสิน (§4)

## R10 — ข้อกำหนด

บนมือถือ ทางเข้าหลักของการบันทึกการปลูกคือ **การสแกน QR ที่ติดอยู่กับแปลงจริง** ไม่ใช่การไล่เมนู
เกษตรกรเดินไปที่แปลง สแกนป้าย แล้วบันทึกกิจกรรมของแปลงนั้นได้ทันที
หน่วยที่ผูกกับป้ายคือ **แปลง** (ตาม R8 ที่เลิกทำรายต้น และตามการเปลี่ยนคำเรียกเป็นแปลงเป็นหลัก)

## 2. ประเด็นความปลอดภัยที่ต้องตัดสินก่อนสร้าง

ป้ายที่แขวนกลางแปลง **ใครเดินผ่านก็สแกนได้** ต่างจาก QR บนหีบห่อที่ผู้ซื้อเป็นคนสแกน
ปัจจุบัน QR ระดับรอบปลูกเปิดสาธารณะและตอบกลับ: ชื่อฟาร์ม ประเภทฟาร์ม อำเภอ จังหวัด ชื่อแปลง ขนาดแปลง ชนิดพืชและสายพันธุ์ วิธีเพาะปลูก
(`apps/backend/services/trace-service/resolve-generic.js:19-29` `toPublicFarm`, และบล็อก `PLANTING_CYCLE` ที่ `:136-152`)

แปลว่าถ้าใช้ QR ตัวเดียวกันไปแขวนที่แปลง คนแปลกหน้าที่เดินผ่านจะรู้ว่าฟาร์มนี้ชื่ออะไร ปลูกอะไร เนื้อที่เท่าไร
สำหรับพืชควบคุมอย่างกัญชา นี่คือการประกาศเป้าหมายให้คนภายนอก

**ข้อเสนอ: แยก QR สองชนิดออกจากกัน ห้ามใช้รหัสเดียวกัน**

| | ป้ายปฏิบัติงาน (แขวนที่แปลง) | QR สืบย้อน (บนผลผลิต/หีบห่อ) |
|---|---|---|
| คนสแกน | เกษตรกร/ทีมงาน/ผู้ตรวจ | ผู้บริโภค |
| ต้องล็อกอิน | **ใช่** | ไม่ |
| สแกนแล้วได้อะไร | เปิดหน้าบันทึกกิจกรรมของแปลงนั้น | หน้าสืบย้อนสาธารณะตาม R9 |
| คนแปลกหน้าสแกนแล้วเห็นอะไร | ไม่เห็นข้อมูลฟาร์มเลย (อย่างมากคือ "ป้ายนี้อยู่ในระบบ GACP") | ตาม R9 |

## 3. สิ่งที่ต้องสร้าง (ถ้า §4 ตัดสินแล้ว)

1. รหัสป้ายระดับแปลง (opaque ไม่สื่อความหมาย ไม่เดาต่อได้) + ตารางผูกป้ายกับแปลง
2. หน้าพิมพ์ป้าย: ขนาดกันแดดกันฝน มีเลขที่แปลงอ่านด้วยตาได้เป็นตัวสำรองเมื่อสแกนไม่ติด
3. เส้นทาง `สแกน → ยืนยันตัวตน → หน้าบันทึกของแปลงนั้น` พร้อมกรณีสแกนป้ายที่ไม่ใช่ของตัวเอง
4. หน้าบันทึกกิจกรรมบนมือถือ ที่ทำงานตอนสัญญาณไม่ดีได้ (คิวไว้แล้วค่อยส่ง)
5. ทางเข้าสำรองเมื่อป้ายหาย/ชำรุด — ห้ามให้ป้ายเป็นทางเดียวที่บันทึกได้

## 4. คำถามที่ต้องให้ operator ตัดสิน

- **Q10-1 ใช้ client ตัวไหน** — แอป Flutter (มีกล้อง มีออฟไลน์อยู่แล้ว แต่ต้องดูแลสองระบบ และแอปมี wizard ยื่นคำขอ 8 ขั้นของตัวเองซ้ำกับเว็บอยู่แล้ว) หรือเว็บมือถือ (ไม่ต้องติดตั้ง ใช้ดีไซน์ใหม่ที่เพิ่งทำร่วมกันได้ แต่ต้องสร้างตัวสแกนใหม่และออฟไลน์ทำได้จำกัด)
- **Q10-2 ออกป้ายได้เมื่อไร** — R2 กำหนดว่า QR ออกได้หลังได้ใบรับรองเท่านั้น ป้ายปฏิบัติงานเป็นของใช้ภายในฟาร์ม ไม่ใช่ของสาธารณะ จะยอมให้ออกก่อนได้ใบรับรองหรือไม่ (ถ้าไม่ยอม เกษตรกรจะบันทึกการปลูกด้วยการสแกนไม่ได้เลยจนกว่าจะได้ใบ)
- **Q10-3 คนแปลกหน้าสแกนป้ายแล้วควรเห็นอะไร** — ไม่เห็นอะไรเลย / เห็นแค่ว่าป้ายนี้อยู่ในระบบ / เห็นเหมือน QR สาธารณะ
- **Q10-4 ป้ายหนึ่งใบผูกกับอะไร** — แปลงถาวร (ป้ายเดิมใช้ข้ามรอบปลูก) หรือรอบปลูก (เปลี่ยนป้ายทุกรอบ)

## 5. หมายเหตุ

แอปมือถือยิง `GET /api/trace/:qrCode` ซึ่งเป็น endpoint สาธารณะ หลังปิดข้อมูลรั่วตาม R9 (commit 4e8252d8) แอปจะไม่เห็นค่าผลแล็บอีกต่อไป
ถ้าเกษตรกรต้องเห็นข้อมูลของตัวเองแบบเต็ม ต้องต่อผ่าน endpoint ที่ยืนยันตัวตน ไม่ใช่ผ่านหน้าสาธารณะ — รวมอยู่ในงานข้อ 3.3
