# จ่ายงานถึงตัวบุคคล และปิดด่านที่ล้มเปิด — Design

> วันที่: 2026-08-13 · ผู้ตัดสินใจ: operator · สถานะ: รออนุมัติ spec
> ใบนี้คือ **ใบ A** — ใบแรกของชุดที่แตกจากการตรวจทั้งระบบ 2026-08-13 (ใบอื่นอยู่ §9)

## 1. Summary

ระบบมีเจตนา "จ่ายงานถึงตัวบุคคล" เขียนไว้ในโค้ดแล้ว **แต่ด่านทุกด่านล้มแบบเปิด** และไม่มีเส้นทางไหน
เขียนคอลัมน์ที่ด่านอ่าน ⇒ วันนี้ **ผู้ตรวจคนใดก็เดินสถานะคำขอของคนอื่นได้ · การตรวจฟาร์มที่ไม่มี
ผู้ตรวจสักคนก็ยืนยันได้ และผลของมันออกใบรับรองอัตโนมัติ**

ใบนี้ทำสามอย่าง: ให้คอลัมน์เป็นแหล่งความจริงเดียวและมีคนเขียนจริง · เปลี่ยนด่านให้ล้มปิด ·
และเพิ่มทางเปลี่ยนผู้รับผิดชอบ ซึ่งไม่มีอยู่เลยและจำเป็นก่อนจะปิดด่านได้อย่างปลอดภัย

**ไม่สร้างโมเดลใหม่** — `WorkActivity` และ `SlaPolicy` ที่ต้องใช้มีอยู่ครบแล้ว แค่ไม่มีใครใช้

## 3. โครงที่มีอยู่แล้วและใบนี้จะใช้

**ไม่ต้องสร้างอะไรใหม่** — `apps/backend/prisma/schema/work-activity.prisma` มีครบ:

```
WorkActivity   assignedUserId (+relation) · claimedAt · startedAt · completedAt · completedBy
               cancelledAt · cancelReason · dueAt · warningAt · warnedAt · breachedAt
               workType · candidateGroup · state · triggeredAtStage · organizationId

SlaPolicy      workType (unique) · targetHours · warningHours · escalationHours
               labelTH · labelEN · isActive
```

⇒ การมอบหมายพร้อมกำหนดเวลาและการยกระดับ **ถูกออกแบบไว้แล้วทั้งหมด** ที่ผิดคือ**การเดินงานถูก
ส่งถึง `candidateGroup` (กลุ่ม ใครก็คว้า) แทน `assignedUserId` (คนเดียว)**

## 4. การตัดสินใจของ operator ที่ใบนี้ตั้งอยู่ (2026-08-13)

1. **คนจัดคิวคือคนกระจายงาน ไม่ใช่ผู้ทำงาน** — เปรียบเหมือนคนรับเอกสารมาเป็นกองแล้วแจกจ่าย
   ⇒ ไม่มีขั้น "รับงาน" สำหรับคนจัดคิว
2. **มอบให้คนเดียว เห็นเฉพาะคนนั้น คนอื่นแย่งไม่ได้** — ปลายทางกดรับเอง
3. **นาฬิกาเริ่มเมื่อปลายทางกดรับหรือเริ่มตรวจ** — ยังไม่รับ = งานค้างแต่ไม่นับวัน
4. ผู้ตรวจลา/ไม่รับงาน → ปล่อยไว้ก่อน · กรณีรับงานไปแล้วให้เจ้าหน้าที่จัดการกันเอง
5. **หน้าตา dashboard ไม่อยู่ในใบนี้** — ไปใบ D

## 5. Design

### 5.1 แหล่งความจริง

| ตัว | หน้าที่ |
|---|---|
| `WorkActivity` | **บันทึกการทำงานจริง** — ใครถือ กดรับเมื่อไร ครบกำหนดเมื่อไร ยกเลิกเพราะอะไร · เก็บประวัติทุกใบงาน |
| `Application.reviewerId` / `auditorId` | **สำเนาของขั้นปัจจุบัน** ให้ด่านตรวจเร็วโดยไม่ต้อง join · เขียนใน transaction เดียวกับ `WorkActivity` เสมอ |
| `SlaPolicy` | นาฬิกาต่อ `workType` ปรับได้โดยไม่ต้อง deploy |
| ~~`formData.PROVIDERAssignment`~~ | **เลิกใช้** — ต้นเหตุที่ทำให้ด่านไม่เคยทำงาน |

### 5.2 ด่านเดียว ใช้ทุกที่

สกัดเป็นฟังก์ชันบริสุทธิ์ `apps/backend/shared/work-ownership.js` (ไฟล์ใหม่)

```js
// คืน null ถ้าผ่าน · คืน { code, messageTH } ถ้าไม่ผ่าน
// ไม่ throw · ไม่แตะ req/res · ไม่แตะ DB  ⇒ ทดสอบได้โดยไม่ต้องมี node module หรือ Postgres
function checkWorkOwnership({ assigneeId, actorId })
```

เหตุผลที่ต้องบริสุทธิ์: gate เต็มของรีโปนี้รันไม่ได้ทุกที่ · ฟังก์ชันแบบนี้พิสูจน์ RED/GREEN ได้บนเครื่องใดก็ได้

ด่านทั้งหมดเรียกตัวนี้ **ห้ามเขียนเงื่อนไขเอง** — วันนี้เขียนซ้ำ 4 ที่และผิดเหมือนกันหมด

**ขอบเขตของฟังก์ชันนี้ — อ่านก่อนลงมือ:** มันตอบคำถามเดียวคือ *"ผู้กระทำคนนี้เป็นเจ้าของงานชิ้นนี้ไหม"*
มัน **ไม่ใช่** ตัวตรวจว่าผู้รับมอบหมายมีตัวตนจริง/active/role ถูก (ข้อ 3 ใน §5.3) — อันนั้นต้องอ่าน DB
จึงเป็นคนละฟังก์ชัน อยู่ในชั้น service ไม่ใช่ shared · และ **ไม่ใช่** ตัวบังคับว่าต้องระบุผู้ตรวจตอนสร้าง
นัดหมาย (ข้อ 5) ซึ่งเป็นการตรวจ input ของ route หนึ่ง ไม่ใช่การตรวจความเป็นเจ้าของ
⇒ **อย่ายัดสามเรื่องนี้เข้าฟังก์ชันเดียว** จะได้ฟังก์ชันที่ต้องมี DB แล้วทดสอบไม่ได้ ซึ่งทำลายเหตุผลที่สกัดมันออกมา

### 5.4 เปลี่ยนผู้รับผิดชอบ

```
คนจัดคิว/แอดมิน สั่งเปลี่ยน → ใน transaction เดียว:
    WorkActivity เดิม   cancelledAt + cancelReason
    WorkActivity ใหม่   assignedUserId = คนใหม่  (นาฬิกาเริ่มเมื่อเขากดรับ)
    Application         reviewerId / auditorId = คนใหม่
    AuditLog            ใครสั่ง · จากใครเป็นใคร · เพราะอะไร
```

- รับได้จาก `ASSIGNED_FOR_REVIEW` และสถานะคู่ขนานฝั่งตรวจฟาร์ม — **ไม่ใช่แค่ `DOC_FEE_PAID`**
- เวลารวมที่ใช้ไปทั้งเคสยังคำนวณย้อนได้จาก `WorkActivity` ที่ถูกยกเลิก · คนใหม่ได้นาฬิกาใหม่

**ข้อนี้เป็นเงื่อนไขบังคับก่อนเปิดด่าน** — ปิดด่านโดยไม่มีทางเปลี่ยนผู้รับผิดชอบ = เปลี่ยนปัญหาที่ซ่อนอยู่
ให้กลายเป็นคำขอที่ค้างถาวรทันทีที่คนที่ถูกมอบหมายหายไป

## 7. Backfill

แหล่งเดียวคือ `formData.PROVIDERAssignment.reviewerId` (ไม่มีแหล่งอื่น — E4)

| กรณี | ทำอย่างไร |
|---|---|
| id resolve เป็น user จริงและ active | เขียนลงคอลัมน์ |
| id มีแต่ user หายไป/ไม่ active | **ไม่เขียน** · ออกรายงานให้คนจัดคิวมอบหมายใหม่ |
| ไม่มี id แต่สถานะเป็น `ASSIGNED_FOR_REVIEW` | **ไม่เขียน** · รายงานเหมือนกัน |
| นัดตรวจที่ `auditorId` เป็น null | นับและรายงาน — ต้องใส่ชื่อย้อนหลังก่อนเปิดด่าน |

**ต้องรู้จำนวนสามกลุ่มหลังก่อนตัดสินใจเปิดด่าน** — ถ้าเยอะ ให้คนจัดคิวเคลียร์ก่อน
