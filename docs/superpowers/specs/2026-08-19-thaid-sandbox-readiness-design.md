# ThaiD Sandbox Readiness — Design Spec

> Authority chain: read-only 4-lane audit (2026-08-19, workflow wf_f6f1c84e) → the first /council (5 seats, 2 adversarial rounds, chairman synthesis, workflow wf_652cb26b) → operator approved all 4 rulings 2026-08-19. Probes P1 (identity_links EMPTY; 42 active users, 0 with *Hmac) and P3 (backfill --dry-run clean: 34+6+40 candidates, 0 errors, 0 null-source) ran clean before approval.

**Goal:** make the ThaiD (DOPA) login testable end-to-end against the official sandbox (`imauthsbx.bora.dopa.go.th`) on the Phase-0 laptop stack (node + Supabase, no Docker), with the identity/PII shape written CORRECTLY the first time (no data minted in a shape that must later be un-written). Production remains gated on real DOPA registration — out of scope.

**Baseline (audited):** backend adapter/routes/config ~90% complete, fully env-driven (sandbox = pure env swap). Hard blockers: no FE callback page (BORA's 302 → 404); the universal Next proxy drops cookies both directions; SESSION_SECRET undocumented. Correctness traps: scope/pid vs id_token mutual exclusivity; 0% HMAC coverage → existing-farmer P2002→500; MFA bypassed on the IdP path; `identity_links.subject` would store the raw CID against the schema's own written prohibition; zero adapter wire-shape tests.

## Council rulings (binding — dissents recorded, not relitigated)

- **R-A (A2, 4-1):** a user who ENROLLED 2FA must satisfy it on the ThaiD path too. Gate at the mint boundary (`prisma-auth-service.js` `issueTokensForAuthenticatedUser`, where `twoFactorEnabled` is already read at :481) — the IdP path returns the same `mfaRequired` challenge contract the password path returns; `/api/mfa/verify` completes it unchanged. NO factor-set/policy-table abstraction (YAGNI constraint). Rider (unrebutted): the existing-link branch (`thaid-identity-service.js:123-131`) accepts ANY role — extend the role assertion / make it audit-visible so a staff link is not a silent 2FA-free door. Dissent: YAGNI voted A1 (no rows yet; revisit with telemetry) — recorded.
- **R-B (B3-amended, args-over-count; auto-fallback conditional):** the smoke test does NOT touch the universal proxy. nginx leg is DEAD (needs Docker; the proof laptop cannot). Unblock shape (implementation resolution of the chairman's "backend-origin" leg): the THREE IdP calls (`GET /providers`, `POST /:provider/authorize-url`, `POST /:provider/callback`) go DIRECTLY from the browser to the backend origin (`NEXT_PUBLIC_BACKEND_ORIGIN`, default `http://localhost:8000`) with `credentials:'include'` — cookies are host-scoped (ports ignored), so `idp_state` set by :8000 returns on the callback POST to :8000, and `provider_token` minted there is visible to :3000 requests, which the existing proxy already converts cookie→Bearer. Zero changes to `route.ts`. Sandbox `redirect_uri` = `http://localhost:3000/auth/callback/thaid` (shared sandbox creds accept any redirect_uri — manual-citations.md:157-158). **Probe P2 gates this:** the first sandbox round-trip must verify the full cookie flow; if it fails, the council's own conditional makes **B2 (fix the proxy, its own Tier C change, RED-first across all 10 cookie consumers in BOTH directions) the ruling automatically.** Until the proxy is fixed, every ThaiD evidence pack carries the open gate: "the farmer's real flow via the :3000 proxy is NOT yet proven."
- **R-C (C1, 5-0):** account matching uses the keyed-HMAC columns for real: operator runs `scripts/backfill-national-id-hmac.js` (dry-run proven clean) then flips `AUTH_LOOKUP_USE_HMAC=true` (flag flip = operator action, L6). No hash fallback (C2 dead: promotes the codebase's self-documented weakest primitive to the identity-binding decision). Contingency (did NOT materialize in P3): only a P2002/NULL-source in a future dry-run reopens this.
- **R-D (D2 + 3 riders, 5-0):** `identity_links.subject` for ThaiD stores a **domain-separated keyed HMAC**, never the raw CID: (1) derivation input is labelled — `computeLookupHmac('idp:thaid:' + sub)` — so the value is NOT byte-identical to `users.healthIdHmac` (cross-column joinability is forbidden by auth.prisma:344); (2) applied at the ThaiD callback path only — `provider='local'` rows keep their user-id subjects; the schema comment must record which providers store derived subjects; (3) the audit-log `subjectHashOf` (auth-idp.js:155-157, bare unsalted SHA-256 of the same CID) is fixed to the same keyed derivation IN THE SAME CHANGE. D2 ships together with R-C (key-rotation recovery = CID re-match, which needs the HMAC columns live). identity_links is EMPTY (P1) → no backfill.
