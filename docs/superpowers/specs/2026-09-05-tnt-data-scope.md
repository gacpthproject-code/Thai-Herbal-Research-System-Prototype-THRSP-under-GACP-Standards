# T&T — ใครเห็นอะไรได้แค่ไหน (ขอบเขตข้อมูล)

**สถานะ: ร่างเพื่อขออนุมัติ operator** · 2026-09-05
**ต่อยอดจาก** `2026-08-20-planting-tnt-design.md` (R1-R16 อนุมัติแล้ว) — เอกสารนี้ไม่แก้มติเดิม
แต่ตอบคำถามที่มติเดิม **ยังไม่ได้ตอบ** และรายงานจุดที่โค้ดจริงไม่ตรงกับมติ

> คำสั่ง operator 2026-09-05: *"ส่วนไหนเป็นข้อมูลเปิด ที่ทุกคนมาสแกนได้ ... ให้ดูขอบเขตได้เท่าไหร่
> และพนักงานติดตาม จะข้อมูลของฟาร์มได้แค่ไหน ... ทั้งหมดนี้เกี่ยวข้องกับข้อกฎหมายทั้งนั้น"*

---

## 0. หลักที่ใช้ตัดสินทุกแถวในเอกสารนี้

1. ~~**ข้อมูลเปิดมีไว้ให้ตรวจสอบคุณภาพ ไม่ใช่ให้สืบเจ้าของ**~~ — **ยกเลิกโดยมติ operator
   2026-09-05**: *"ยังไม่ต้องสนใจกฎหมาย PDPA ให้อัปโหลด COA และพวกชื่อฟาร์ม และที่อยู่ติดต่อได้
   เมื่อสแกนต้องเห็นทั้งหมด"* ⇒ หลักที่ใช้ในเฟสนี้คือ **คนสแกนเห็นทั้งหมด** ทั้งชื่อฟาร์ม
   ที่อยู่ติดต่อ และไฟล์ COA · เป็นการผ่อนแบบเดียวกับที่ operator เคยผ่อนกฎ residency
   ⇒ **ต้องกลับมาทบทวนก่อนขึ้นเครื่องจริงของกระทรวง** (ดูข้อ 7)
2. **สิ่งที่ยังไม่เกิด ไม่ใช่ข้อมูลสาธารณะ** — ตัวเลขคาดการณ์ แผนการผลิต ปริมาณที่ตั้งใจจะปลูก
   เป็นสถานะทางธุรกิจของเกษตรกร ไม่ใช่ข้อเท็จจริงเกี่ยวกับสินค้าที่วางขายอยู่
3. **เจ้าหน้าที่เห็นได้เท่าที่หน้าที่ตามกฎหมายกำหนด ไม่ใช่เท่าที่ระบบมี** — สิทธิ์เข้าถึงผูกกับ
   ภารกิจที่ได้รับมอบหมาย ไม่ใช่กับตำแหน่ง
4. **การไม่ตอบ ต้องแยกจากการตอบว่าไม่มี** — ระบบอ่านไม่ได้ ต้องไม่แสดงผลเหมือน "ไม่มีข้อมูล"

## 1. ข้อมูลเปิด — คนทั่วไปสแกน QR โดยไม่ล็อกอิน

เส้นทาง: `GET /api/trace/:qrCode` (ไม่มี auth middleware ตลอดสาย)

| ข้อมูล | เปิด | เหตุผล |
|---|---|---|
| เลขใบรับรอง + สถานะจริง (active/หมดอายุ/เพิกถอน) | ✅ | คือคำถามที่คนสแกนมาถาม |
| ชนิดพืช สายพันธุ์ ชื่อวิทยาศาสตร์ | ✅ | คุณสมบัติของสินค้า |
| ตำบล/อำเภอ/จังหวัด | ✅ | แหล่งผลิตระดับที่ตรวจสอบได้ |
| **พิกัด GPS** | ❌ | นำไปหาบ้านได้ · §4.4 ห้ามไว้แล้ว |
| วันปลูก / วันเก็บเกี่ยวจริง | ✅ | ข้อเท็จจริงของล็อตที่ถืออยู่ |
| **น้ำหนักที่เก็บเกี่ยวจริง** (HarvestBatch) | ✅ | ของที่มีอยู่จริง |
| **ปริมาณคาดการณ์ (`estimatedYield`)** | ❌ | **§4.4 + §5 ห้าม — แต่โค้ดเปิดอยู่จริงจนถึงวันนี้ ดูข้อ 4** |
| ผล Lab + ไฟล์ COA | ✅ **เปิด** | มติ operator 2026-09-05 — **แทนที่ R9** · อัปโหลดได้และคนสแกนเห็นได้ |
| ปุ๋ย/สารที่ใช้ | ⚠️ สรุปประเภท + จำนวนครั้ง + เว้นระยะก่อนเก็บ | ไม่แสดงชื่อสาร/สูตร (ความลับทางการค้า) |
| ชื่อฟาร์ม | ✅ **เปิด** | มติ operator 2026-09-05 — แสดงเต็มตามที่จดทะเบียน |
| ชื่อ/ที่อยู่ติดต่อเกษตรกร | ✅ **เปิด** | มติ operator 2026-09-05 — คนสแกนต้องเห็นทั้งหมด ไม่ต้อง opt-in |
| เลขบัตรประชาชน เอกสารสิทธิ์ที่ดิน ไฟล์แนบ | ❌ | ไม่มีเหตุผลใดให้เปิด |
| id ภายในของฟาร์ม/คำขอ | ❌ | เป็นมือจับสำหรับไล่เดา (ปัจจุบัน `toPublicFarm` ไม่ส่งออก — ถูกแล้ว) |

## 2. เกษตรกร — เจ้าของข้อมูล

| การกระทำ | ได้ | ขอบเขต |
|---|---|---|
| ดูข้อมูลฟาร์ม/รอบปลูก/ล็อตของตัวเอง | ✅ | เฉพาะของตัวเอง — ownership guard แบบเดียวกับ certificates |
| อัปเดตบันทึกการปลูก | ✅ | **จนถึงวันตัดเท่านั้น** (R11/R12) หลังตัดแช่แข็ง |
| แก้ไขหลังแช่แข็ง | ❌ | ต้องเพิ่มรายการใหม่ ไม่ทับของเดิม (§7.4) |
| ข้อมูลติดต่อบน public | — | **แสดงเสมอ** ตามมติ 2026-09-05 · ไม่ใช่ opt-in อีกต่อไป |
| ดูข้อมูลฟาร์มคนอื่น | ❌ | แม้อยู่ตำบลเดียวกัน |
| เห็นบันทึกของผู้ตรวจเกี่ยวกับตน | ⚠️ **ต้องตัดสิน — ดูข้อ 5.2** | |

## 3. พนักงานติดตาม — คำถามที่มติเดิมไม่เคยตอบ

สเปก 2026-08-20 §5 ระบุว่า role ห้อง Lab/โรงงานอยู่นอกเฟส แต่ **ไม่ได้พูดถึงขอบเขตของ
เจ้าหน้าที่ติดตามเลย** นี่คือช่องว่างที่ต้องปิด

**มติ operator 2026-09-05: *"เห็นข้อมูลทั้งหมด"* + *"ฟาร์มทุกประเทศ"***
ตารางที่เคยเสนอให้จำกัดเฉพาะฟาร์มที่ได้รับมอบหมาย และให้ mask เลขบัตร **ไม่ใช่มติ** —
เก็บไว้ในประวัติ git เท่านั้น ของจริงคือตารางนี้

| ข้อมูล | เห็น | หมายเหตุ |
|---|---|---|
| ฟาร์มทุกแห่งทั้งประเทศ | ✅ เต็ม | ไม่ผูกกับการมอบหมายงาน |
| PII เกษตรกร (ชื่อ เบอร์ ที่อยู่) | ✅ | ตามมติ |
| เลขบัตรประชาชนเต็ม | ✅ | ตามมติ — ไม่ mask |
| ไฟล์เอกสารแนบ | ✅ | ผ่าน viewer ในหน้า ไม่ดาวน์โหลดอัตโนมัติ |
| ข้อมูลการเงิน/ใบแจ้งหนี้ | ❌ | คนละหน้าที่ ไม่ได้อยู่ในคำว่า "ติดตาม" |
| **ทุกการเปิดดูต้องบันทึก audit** | ✅ บังคับ | PDPA ม.39 — ไม่ใช่การจำกัดขอบเขต แต่ทำให้ขอบเขตที่กว้างตรวจย้อนได้ |

ขอบเขตที่กว้างขึ้นทำให้หน้าที่ตามกฎหมาย **หนักขึ้น ไม่ใช่เบาลง** และหน้าที่นั้นอยู่ที่
*ผู้ควบคุมข้อมูล* คือแพลตฟอร์ม ไม่ใช่ที่ตัวพนักงาน — PDPA ม.37(1) สั่งให้มีมาตรการป้องกัน
การเข้าถึงหรือใช้โดยมิชอบ · ม.39 สั่งให้บันทึกรายการรวมถึงการเข้าถึง
รายละเอียดการออกแบบอยู่ที่ `docs/design/2026-09-05-tnt-loop-and-farmer-updates.md` §3.3

## 4. ⚠️ จุดที่โค้ดไม่ตรงกับมติ — พบและแก้แล้ววันนี้

**`estimatedYield` ถูกเปิดบนเส้นทางสาธารณะ** ทั้งที่มติห้ามไว้สองที่ (§4.4 บรรทัด 80, §5 บรรทัด 93)

ใครก็ตามที่ถือ QR เห็นตัวเลขที่ฟาร์มคาดว่าจะผลิตได้ทั้งฤดู วางอยู่ข้างชื่อฟาร์ม อำเภอ และวันปลูก —
เป็นการยื่นจุดยืนในการต่อรองให้อีกฝั่งของโต๊ะ โดยระบบรับรองที่เกษตรกรถูกบังคับให้ใช้

แก้แล้ว: `resolve-generic.js` ตัด `estimated` ออกจาก payload สาธารณะ (เก็บ `actual` ไว้)
พร้อมเทส `trace-generic-no-projected-yield.test.js` ที่ยืนยันว่า**คีย์หายไปจริง ไม่ใช่เป็น null**
และยืนยันว่า**สำเนาใน cache ก็ถูกตัดด้วย** — เพราะ cache คือสิ่งที่คนสแกนส่วนใหญ่ได้อ่าน

ไม่มี consumer ไหนอ่านฟิลด์นี้ (grep ทั้ง web และ backend) — เปิดไว้โดยไม่มีใครได้ประโยชน์

## 5. สิ่งที่ต้องให้ operator ตัดสิน

### 5.1 ชื่อฟาร์มบนหน้าสาธารณะ — **ตัดสินแล้ว 2026-09-05: แสดงเต็ม**

operator: *"พวกชื่อฟาร์ม และที่อยู่ติดต่อได้ เมื่อสแกนต้องเห็นทั้งหมด"* ⇒ ไม่ต้อง mask
ไม่ต้องมีช่อง "ชื่อที่แสดงต่อสาธารณะ" แยก และไม่ต้องให้เกษตรกร opt-in

### 5.2 เกษตรกรเห็นบันทึกของผู้ตรวจเกี่ยวกับตนได้ไหม — **ตัดสินแล้ว 2026-09-05: ได้**

operator: *"อ้างอิงตามกฎหมาย PDPA ได้เลย"* ⇒ **PDPA ม.30** ให้เจ้าของข้อมูลมีสิทธิขอเข้าถึง
และขอรับสำเนาข้อมูลส่วนบุคคลของตน · บันทึกที่ผู้ตรวจเขียนเกี่ยวกับเกษตรกรรายนั้นเป็นข้อมูล
ส่วนบุคคลของเกษตรกร จึงเปิดให้เจ้าตัวดูได้เป็นค่าตั้งต้น

**แต่ไม่ใช่ทุกแถว** — ม.30 วรรคสองให้ปฏิเสธได้เมื่อเป็นไปตามกฎหมาย/คำสั่งศาล หรือกระทบสิทธิ
เสรีภาพของบุคคลอื่น ⇒ ต้องมีสวิตช์รายรายการพร้อมเหตุผลที่บันทึกไว้ ไม่ใช่เปิดหมดหรือปิดหมด
(ออกแบบที่ `docs/design/2026-09-05-tnt-loop-and-farmer-updates.md` §3.2)

### 5.3 ขอบเขต "พนักงานติดตาม" — **ตัดสินแล้ว 2026-09-05: เห็นข้อมูลทั้งหมด**

operator: *"เห็นข้อมูลทั้งหมด"* ⇒ ตาราง §3 ที่เสนอให้จำกัดเฉพาะฟาร์มที่ได้รับมอบหมาย
และ mask เลขบัตรประชาชน **ไม่ใช่มติ** พนักงานติดตามเห็นข้อมูลฟาร์มได้ครบ

สองเรื่องที่มติข้อนี้ **ไม่ได้ตอบ** และยังต้องทำ เพราะเป็นคนละคำถามกับ "เห็นได้แค่ไหน":
1. **ทุกการเปิดดูต้องบันทึก audit** — ใครเปิดข้อมูลของใครเมื่อไร ต้องตอบได้
   (เป็นข้อกำหนด PDPA ม.39 ไม่ใช่การจำกัดขอบเขต)
2. ~~**"ทั้งหมด" หมายถึงทุกฟาร์ม หรือทุกข้อมูลของฟาร์มที่รับผิดชอบ**~~ —
   **ตอบแล้ว 2026-09-05: *"ฟาร์มทุกประเทศ"*** พนักงานติดตามหนึ่งคนเปิดดูฟาร์มทั้งประเทศได้
   ⇒ ข้อ 1 ข้างบน (audit ทุกการเปิดดู) จึงกลายเป็นข้อบังคับ ไม่ใช่ข้อเสนอ

## 6. ตรวจครบทุกเส้นทางสาธารณะแล้ว (2026-09-05)

เอกสารฉบับแรกตรวจแค่ `:qrCode` เส้นเดียว และเขียนว่าเหลืออีกสามเส้น — **ผิด มีหกเส้น**

| เส้นทาง | ต้องล็อกอิน | ผลการตรวจ |
|---|---|---|
| `GET /api/trace/:qrCode` | ไม่ | ตรวจแล้วรอบแรก · ตัด `estimatedYield` ออกไปแล้ว |
| `GET /api/trace/:qrCode/qr` | ไม่ | คืนภาพ QR เท่านั้น |
| `GET /api/trace/plot-cycle/:qrCode` | ไม่ | ไม่พบ PII/พิกัด/ตัวเลขคาดการณ์ |
| `GET /api/trace/batch/:batchId` | ไม่ | **พบรูรั่ว — แก้แล้ว** |
| `GET /api/trace/lot/:lotId` | ไม่ | **พบรูรั่ว — แก้แล้ว** |
| `GET /api/trace/verify/:entityType/:entityId` | ไม่ | ตอบแค่ "มี/ไม่มีแถวนี้" · เป็น oracle แต่ id เป็น UUID เดาไม่ได้ |

`routes/api/trace/lots.js` มี `authenticateHealth` ทุกเส้น — ไม่ใช่ประตูสาธารณะ

### รูรั่วที่พบและแก้แล้ว

สองเส้น batch/lot ประกอบ payload เองในไฟล์ route (ไม่ผ่าน resolver ที่ถูกตรวจไปแล้ว)
และส่ง **กุญแจหลักของฐานข้อมูล** ออกให้คนที่ไม่ได้ล็อกอิน:

- `farm.id` — กุญแจหลักของฟาร์ม **(สำคัญที่สุด)**
- `source.plot.plotId`, `source.plot.cyclePlotId`, `source.cycle.cycleId`

การสแกนหนึ่งครั้งคือการสแกน **หนึ่งกล่อง** แต่ `farm.id` ทำให้ผู้สแกนโยงทุกล็อตทุกรุ่น
ของฟาร์มนั้นเข้าด้วยกันข้ามการสแกน และยิง `/trace/verify/FARM/<id>` ยืนยันได้ว่ามีอยู่จริง
ขัดกับหลักข้อ 1 ของเอกสารนี้เอง ("ข้อมูลเปิดมีไว้ให้ตรวจสอบคุณภาพ ไม่ใช่ให้สืบเจ้าของ")
และตาราง §1 ที่ระบุ id ภายในว่า ❌ "เป็นมือจับสำหรับไล่เดา"

**ไม่มีหน้าจอไหนแสดง id เหล่านี้เลย** — มันถูกส่งต่อมาเพราะแถวถูกโหลดมาอยู่แล้ว

**สิ่งที่คงไว้:** `lotId` และ `batchId` เพราะเป็น *ที่อยู่สาธารณะจริง* — QR ที่พิมพ์บนกล่อง
ชี้ไปที่ `/trace/lot/<id>` การไม่คืนค่าจะทำให้การนำทางที่ QR มีไว้เพื่อสิ่งนั้นพัง ·
ชื่อแปลงและชื่อรอบปลูกคงไว้ เพราะเป็นสิ่งที่ผู้บริโภคใช้ได้จริง

ปักหมุดด้วย `apps/backend/__tests__/unit/public-trace-hands-out-no-internal-ids.test.js`
ซึ่งกวาดไฟล์ route ทุกไฟล์ใต้ `routes/api/trace/` และ **จะแดงถ้ามีไฟล์ใหม่โผล่มาโดยไม่ถูกตรวจ**

### ชื่อแปลง / ชื่อรอบปลูก — **ตัดสินแล้ว 2026-09-05: ไม่เปิด**

ฉบับแรกของเอกสารนี้คงไว้ตามการตัดสินของผู้พัฒนา (ช่วยตรวจสอบย้อนกลับ ไม่ใช่ PII)
operator ตัดสินตรงกันข้าม: *"ไม่ควรเห็น — ตัดออกจากหน้าสาธารณะ"*

เป็นการตั้งชื่อเรียกภายในของฟาร์ม — ชื่อแปลงอาจมีชื่อคน ("แปลงหลังบ้านลุงมี") และชื่อรอบ
ปลูกบอกจังหวะการผลิต · ผู้บริโภคที่ตรวจคุณภาพต้องการเลขใบรับรอง ชนิดพืช อำเภอ วันที่
และน้ำหนักจริง ซึ่งได้ครบอยู่แล้ว

ตัดบล็อก `source` ทั้งก้อนออกจากทั้ง `/trace/batch/:batchId` และ `/trace/lot/:lotId`
พร้อมกับ query หา integrity record ที่มีไว้ป้อนบล็อกนั้นอย่างเดียว — **ลดการอ่านฐานข้อมูล
ไปหนึ่งครั้งต่อการสแกนหนึ่งครั้ง** · ชื่อฟาร์มยังอยู่ (ข้อ 5.1 ยังรอมติ)

## 7. รายการที่ผ่อนไว้ในเฟสนี้ และต้องกลับมาก่อนขึ้นเครื่องจริงของกระทรวง

มติ 2026-09-05 ผ่อนเรื่อง PDPA ไว้ชั่วคราวเพื่อให้เดโมใช้งานได้เต็ม เขียนรายการไว้ตรงนี้
เพื่อให้ "ผ่อนชั่วคราว" ไม่กลายเป็น "ลืมไปเลย" — แบบเดียวกับที่ทำกับกฎ residency

| ผ่อนอะไร | ผลตอนนี้ | ต้องตัดสินใหม่เมื่อ |
|---|---|---|
| ชื่อฟาร์มบนหน้าสาธารณะ | แสดงเต็ม | ขึ้นเครื่องจริงของกระทรวง |
| ที่อยู่/ข้อมูลติดต่อเกษตรกร | แสดงเต็ม ไม่ใช่ opt-in | ขึ้นเครื่องจริงของกระทรวง |
| ไฟล์ COA บนหน้าสาธารณะ (แทนที่ R9) | เปิดให้ดาวน์โหลด — **เอกสาร COA จริงมีชื่อ ที่อยู่ และเลขอ้างอิงของเกษตรกรพิมพ์อยู่ในตัวเอกสาร** | ขึ้นเครื่องจริงของกระทรวง |

**ข้อเดียวที่ยังไม่เปลี่ยน และขอให้ยืนยัน**: **พิกัด GPS** ยังปิดอยู่ · ต่างจากสามข้อบน
ตรงที่มันไม่ใช่เรื่องความเป็นส่วนตัว แต่เป็นเรื่องความปลอดภัยทางกายภาพ — พิกัดพาคนไปถึงแปลง
และแปลงกัญชาเป็นเป้าการโจรกรรม · ที่ตั้งระดับตำบล/อำเภอ/จังหวัดเปิดอยู่แล้วและตรวจสอบที่มาได้
ถ้าต้องการเปิดพิกัดด้วย สั่งมาได้ครับ จะเปิดให้
