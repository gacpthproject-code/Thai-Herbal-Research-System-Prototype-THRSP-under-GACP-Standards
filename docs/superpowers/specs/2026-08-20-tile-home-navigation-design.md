# Tile Home Navigation — design

**วันที่:** 2026-08-20 · **สถานะ:** อนุมัติโดย operator (brainstorm รอบ tile-home) ·
**ที่มา:** feedback ผู้ใช้จริงว่า navigation เดิม "ออกแบบเข้าใจยาก" + หลักฐานตรวจพบเอง:
เมนูบนหัวฝั่ง provider มีสองปุ่มชี้ `/provider/audits` เหมือนกัน, เมนูเกษตรกร ~10 รายการแน่นจนอ่านยาก ·
แบบอ้างอิงที่ operator ชี้: หน้า e-Service ของกรมการจัดหางาน (tile launcher) — เอา **โครง** มา ไม่เอาสี

## 2. โครงหน้า tile home

- หลัง login ทุก role เข้า `home` ของฝั่งตัวเอง — tile grid 2 คอลัมน์ desktop, 1 คอลัมน์มือถือ (≥390px)
- แต่ละ tile: ไอคอน + ชื่อเมนู + คำอธิบาย 1 บรรทัด
- **แดชบอร์ดเดิมไม่หาย** — เป็น tile แรก "ภาพรวม" เนื้อหาข้างในคงเดิมทุกหน้า
- tile ที่ role ไม่มีสิทธิ์ = **ไม่แสดง** (ห้าม render แบบ disabled ให้กดไม่ได้ — บทเรียนช่อง X3.5)
- ยกเว้นเคสสื่อสารที่ตั้งใจ: "การปลูก" ก่อนมีใบรับรอง แสดงพร้อมไอคอนล็อก + เหตุผล
  "เปิดใช้เมื่อคุณได้รับใบรับรอง GACP" (สอดคล้อง R2 ของ spec planting-tnt — สถานะไม่ใช้สีอย่างเดียว
  ต้องมีไอคอน+ข้อความตาม DESIGN.md)

### Signature element (ตาม frontend-design skill — จุดจำหนึ่งเดียว ที่เหลือเงียบ)

Tile ของเราไม่ใช่ปุ่มโง่แบบ DOE: **tile เป็น launcher ที่มีชีวิต** — แต่ละใบแสดง chip
สถานะจริงจากระบบ เช่น คำขอรับรอง → "2 รายการรอคุณดำเนินการ", ใบรับรอง → "ใช้งานได้ 1 ใบ",
การชำระเงิน → "มียอดค้างชำระ" · เกษตรกรมองหน้า home ครั้งเดียวรู้ว่าต้องไปที่ไหน —
นี่คือคำตอบเชิงดีไซน์ต่อ feedback "เข้าใจยาก" ไม่ใช่แค่จัดปุ่มใหม่ · chip เป็น optional ต่อ tile
(ไม่มีข้อมูล = ไม่แสดง chip, ห้ามแสดง "0 รายการ")

## 3. SSOT navigation config (หัวใจทางเทคนิค — ฆ่าปัญหาเมนูซ้ำที่ราก)

- ไฟล์ config เดียวต่อ role: `{ key, path, ชื่อไทย, คำอธิบาย, icon, เงื่อนไขสิทธิ์/ล็อก, chipSource? }`
- ทั้ง tile grid และ bottom nav มือถือ generate จาก config นี้ — **ห้ามมีที่อื่นประกาศเมนู**
  (เคสสองปุ่มชี้ `/provider/audits` จะเกิดไม่ได้อีกเพราะไม่มีที่ให้พิมพ์เมนูมือ)
- constants เมนูเดิม (`constants.ts` ฝั่ง health ที่ integrity-check ตรวจ path อยู่แล้ว) ยุบเข้า config นี้
  ให้ probe เดิมตรวจต่อได้

## 4. มาตรฐานการสร้าง (ผูกกับ skill ของ repo — บังคับ ไม่ใช่แนะนำ)

**gacp-design-tokens:**
- พื้น tile = `bg-card` (flip dark เอง) — ห้าม `bg-white` เปล่า · ไอคอน/ขอบใช้ leaf ตาม
  contrast contract: ข้อความบนปุ่มทึบ = `bg-leaf-700` ขึ้นไป, `bg-leaf`/`leaf-600` = ของตกแต่งเท่านั้น
- radius/เงาจาก token (`rounded-lg`, `shadow-leaf-card`) · tile สร้างจาก primitives
  (`card.tsx`/`button.tsx`) ห้าม hand-roll · ห้าม `emerald-*`/`zinc-*`/`slate-*`/`!important` ใหม่
- focus ring ต้องเห็นครบทุก tile (tab ไล่ทั้งหน้า) · `prefers-reduced-motion` เคารพผ่าน token เดิม

**thai-ui-copy:**
- ทะเบียนคำ: **คุณ** ทุกจุด · ไม่มี em dash · เว้นวรรคหน้า ๆ และรอยต่อไทย/Latin
- ชื่อ tile = สิ่งที่ผู้ใช้ควบคุม ("คำขอรับรอง" ไม่ใช่ชื่อระบบภายใน) · คำอธิบาย 1 บรรทัด
  บอกว่าไปทำอะไรได้ ไม่ใช่คำโฆษณา · chip บอกจำนวน+การกระทำ ("2 รายการรอคุณดำเนินการ")
- วันที่ใน chip (ถ้ามี) ผ่าน `formatThaiDate` เท่านั้น

**frontend-design:** ความกล้าใช้ที่เดียวคือ live-chip tiles — ที่เหลือเรียบวินัย:
ไม่มี animation ประดับ, hero ของหน้า home คือ grid เอง ไม่ต้องมี banner ต้อนรับ

## 5. การรื้อ

- ถอดแถวลิงก์เมนูออกจาก header ทั้ง 3 ฝั่ง (health / provider / admin) — เหลือ slim bar ตาม N2
- ปุ่ม "← หน้าหลัก" เพิ่มในทุกหน้าใน (ตำแหน่งเดียวกันเสมอ ใต้ slim bar)
- bottom nav มือถือฝั่ง health คงไว้ 5 ปุ่ม: หน้าหลัก · คำขอ · ใบรับรอง · การปลูก · โปรไฟล์
  (generate จาก config เดียวกัน)
- หน้าเนื้อหาข้างในทุกหน้า **ไม่แตะ** ในงานนี้

## 6. ไม่ทำในงานนี้

Mobile app (Flutter) ใช้โครงเดิมไปก่อน (งานแยก) · การแก้ปุ่มตาย/ช่อง X3.5 ในหน้าใน
(เป็นของ UI-debt sweep ที่จะรัน button crawler แยก) · การออกแบบหน้า T&T
(spec `2026-08-20-planting-tnt-design.md` — หน้าใหม่ของมันจะเกิดบน IA นี้)

## 7. การทดสอบ / DoD

- Tier ตาม `tier-check.sh` (คาด B — UI ไม่แตะเงิน/auth) · RED-first กับ behavior:
  config SSOT generate ครบทุกเมนูเดิม (ไม่มีเมนูหาย — เทียบ inventory ก่อน/หลัง),
  tile ไม่โชว์เมนูที่ไม่มีสิทธิ์, ล็อกการปลูกโชว์ถูกเงื่อนไข

- **View-pack ตาม gacp-view-in-the-loop**: เดินจริงทุก role, มือถือ 390×844 เป็นหลักฝั่งเกษตรกร
  + desktop 1920, ก่อน/หลัง เทียบกันในหน้าเดียว
