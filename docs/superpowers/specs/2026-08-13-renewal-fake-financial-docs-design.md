# ปิดเส้นทางต่ออายุที่ผลิตเอกสารการเงินไม่มีหลังบ้าน — Design

> วันที่: 2026-08-13 · ผู้ตัดสินใจ: operator · สถานะ: รออนุมัติ spec
> ใบนี้คือ **ใบ 1 จาก 4** ที่แตกออกมาจากงาน "fee SSOT (GOALS.md G1)" — ดู §8

## 1. Summary

หน้าต่ออายุใบรับรองฝั่งเว็บพา applicant เดิน wizard 4 ขั้น (upload → quotation → invoice →
payment) โดยที่ **ขั้นสุดท้ายรับเงินไม่ได้ และขั้นแรกยื่นคำขอไม่ได้** — ปุ่มยื่นยิงไปยัง path ที่ไม่มี
route อยู่จริง ระหว่างทางหน้าจอวาดใบเสนอราคาและใบแจ้งหนี้เป็นเอกสารพร้อมจำนวนเงินตัวอักษรไทย
จากค่าคงที่ฝั่ง frontend ซึ่งเป็นเลขที่ไม่ตรงกับกติกาที่ operator เพิ่งตัดสิน ฝั่งแอปมือถือมีจอต่ออายุที่
กดยื่นแล้วขึ้นข้อความ "ยื่นคำขอต่ออายุสำเร็จ" โดยไม่ส่งอะไรไปที่ระบบเลย

ใบนี้ **ปิดเส้นทางต่ออายุออนไลน์ทั้งเส้น** จนกว่าใบ 3 จะสร้าง flow ต่ออายุจริงตามกติกาจ่ายครั้งเดียว
ไม่ใช่การซ่อมหน้าจอทีละจุด

## 4. ข้อห้ามสำคัญ — 404 ที่ R2 เป็นตาข่ายกันโดยบังเอิญ

**ห้ามแก้ path ที่ R2 ให้ถูกในใบนี้ และห้ามแก้จนกว่าใบ 3 จะเสร็จ**

เหตุผล: `renewal-service.createRenewalApplication` สร้าง `Application` โดยไม่ตั้ง `serviceType`,
`phase1Amount`, `phase2Amount` (`apps/backend/services/renewal-service.js:305-319`) แถวจึงเกิดมา
พร้อม default ของ schema — `serviceType = "new_application"`, `phase1Amount = 5535`,
`phase2Amount = 27675` (`apps/backend/prisma/schema/application.prisma:34,65,80`)

⇒ ถ้า "แก้ 404 ให้ยิงถูก" ระบบจะเริ่มสร้างคำขอต่ออายุจริงที่ถูกตั้งราคาเป็น **2 งวด 33,210 ต่อรูปแบบ
การปลูก** ซึ่งขัดกติกาจ่ายครั้งเดียว 30,000 ต่อใบ — คือเปลี่ยนจาก "ยื่นไม่ได้" เป็น "ยื่นได้แต่ราคาผิด
และมีแถวผิดค้างในฐานข้อมูล" ซึ่งแย่กว่า

ข้อห้ามนี้ต้องเขียนเป็นคอมเมนต์ติดไว้ที่บรรทัดที่เกี่ยวข้อง ไม่ใช่อยู่แต่ในเอกสารฉบับนี้

## 5. Goals / Non-Goals

**Goals**
- ผู้ใช้เข้าถึงเส้นทางต่ออายุออนไลน์ไม่ได้ และไม่เห็นเอกสารการเงินใด ๆ จากเส้นทางนี้
- ไม่มีหน้าจอใดในระบบแจ้ง "ยื่นคำขอต่ออายุสำเร็จ" โดยไม่มีคำขอเกิดขึ้นจริง
- สัญญา API ที่ประกาศออกไปตรงกับสิ่งที่มีอยู่จริง
- เหตุผลที่ห้ามแก้ 404 ถูกบันทึกไว้ในโค้ด ป้องกันคนแก้ด้วยความหวังดีรอบหน้า

**Non-Goals**
- ไม่สร้าง flow ต่ออายุใหม่ (ใบ 3)
- ไม่แตะตารางค่าธรรมเนียมหรือ fee SSOT (ใบ 2)
- ไม่แตะ `applications.js:378` เรื่อง `serviceType` ไม่มี allowlist (ใบ 0 — เป็นเรื่องความปลอดภัย
  บนเส้นเงิน คนละ tier ห้ามปนใบนี้)
- ไม่แตะ `subscription-order-service.js:360` (เส้นเงิน "ต่ออายุ" ของ subscription คนละเรื่องกัน)
- ไม่ลบไฟล์ step ทิ้ง — ใบ 3 จะใช้โครงเดิมบางส่วน การลบทำให้ diff ของใบ 3 อ่านยากขึ้นโดยไม่จำเป็น

## 6. Design

### 6.1 เว็บ — เหลือหน้าเดียว
`apps/web-app/src/app/health/applications/renewal/page.tsx` เปลี่ยนเป็นหน้าสถานะเดียว:
หัวข้อ "ยังไม่เปิดให้บริการต่ออายุออนไลน์" + คำอธิบายสั้น + ช่องทางติดต่อเจ้าหน้าที่ + ปุ่มกลับไปหน้า
รายการใบรับรอง

- คัดลอกข้อความและช่องทางติดต่อจาก `RenewalAdvisoryBanner` ที่มีอยู่ (`client-view.tsx:63-80`)
  เพื่อไม่ให้เกิดข้อความชุดที่สอง — i18n เดิมใช้ `dict.renewalAdvisory` ใช้ต่อได้ทันที
- `client-view.tsx` และ step ทั้ง 4 ไฟล์ **ไม่ถูก render อีกต่อไป** แต่ยังคงไว้ในรีโปสำหรับใบ 3
- **ทางเข้าทั้ง 4 จุดใน §3 ไม่ต้องแก้** — ลิงก์ยังชี้มาที่ `/health/applications/renewal` เหมือนเดิม
  แล้วผู้ใช้จะเจอหน้าสถานะพร้อมคำอธิบายและช่องทางติดต่อ · เลือกท่านี้เพราะมีจุดแก้จุดเดียวแทนห้าจุด
  และผู้ใช้ที่กดได้คำตอบว่าทำไม ดีกว่าปุ่มที่หายไปเฉย ๆ หรือปุ่มที่กดไม่ได้โดยไม่บอกเหตุผล
- ผลตามมา: `certificates-renewal-cta.test.ts:26-31` ที่ตรึงลิงก์ CTA ไว้ **ยังเขียวตามเดิม ไม่ต้องแก้**

### 6.2 มือถือ — ห้ามแจ้งสำเร็จปลอม
`_submitRenewal()` (`renewal_application_screen.dart:242-248`) ต้องไม่แสดงข้อความสำเร็จ
ทางที่เลือก: ปิดปุ่มยื่น (disabled) + ข้อความเดียวกับเว็บว่ายังไม่เปิดให้บริการ
**ห้าม** ใช้วิธีเปลี่ยนข้อความ SnackBar เป็นข้อความอื่นแล้วคง flow เดิม — ปุ่มที่กดได้แต่ไม่ทำอะไรคือ
ปัญหาเดียวกันในรูปแบบใหม่

### 6.3 สัญญา API
ลบ block `/certificates/{certificateId}/renew` (`openapi/certificate-service.yaml:376-440`) ทั้งก้อน

**แก้ 2026-08-13 — ข้อความเดิมของ spec นี้ผิด** เคยเขียนว่า *"ไม่ได้ถูก codegen เข้า mobile จึงเป็น
เอกสารสัญญาล้วน การลบไม่กระทบ runtime"* · ครึ่งแรกจริง (`apps/backend/config/swagger.js:192-196`
สร้าง spec ที่เสิร์ฟจาก jsdoc ของ route ไม่ได้อ่านไฟล์นี้) แต่**ครึ่งหลังไม่จริง**:

`.github/workflows/generate-api-clients.yml` trigger บน `openapi/**/*.yaml` (`:15-21`) และมี
`certificate-service` อยู่ในรายการ (`:62`) → รัน `openapi-generator-cli` (`:51`) สร้าง client ลง
`apps/web-app/src/generated/api/<service>` (`:76`)

⇒ **การลบ path นี้จะเปลี่ยน generated client ที่ commit อยู่ในรีโป** ผู้ทำต้อง:
1. ตรวจว่ามีโค้ดไหนเรียก operation `renewCertificate` จาก client ที่ generate ไว้หรือไม่
   (`grep -rn "renewCertificate" apps/web-app/src apps/mobile-app/lib`)
2. ถ้าไม่มีผู้เรียก → ลบได้ และต้อง regenerate/commit client ที่เปลี่ยนไปในใบเดียวกัน
   ไม่งั้น workflow จะ auto-commit ทีหลังแล้ว diff ไปโผล่ในใบอื่น
3. ถ้ามีผู้เรียก → **หยุด** เพราะแปลว่ามีโค้ดที่เรียก endpoint ที่ไม่มีอยู่จริง ซึ่งเป็น finding ใหม่
   ไม่ใช่ของที่ใบนี้ครอบ

### 6.4 กันคนแก้ย้อนกลับ
คอมเมนต์สั้นที่ `client-view.tsx:227` และที่ `renewal-service.js:305-319` ระบุว่า path นี้ต้องไม่ถูก
"แก้ให้ถูก" จนกว่า renewal จะมี milestone และราคาของตัวเอง พร้อมชี้มาที่เอกสารฉบับนี้

## 11. การตัดสินใจของ operator ที่ใบนี้อ้างอิง (2026-08-13)

1. ค่าธรรมเนียมต่ออายุ = **30,000 บาท เป็นค่าธรรมเนียมรัฐ จ่ายครั้งเดียวต่อใบ** ไม่คูณตามรูปแบบการปลูก
2. ต่ออายุมีค่าแพลตฟอร์ม 10% + VAT 7% บนค่าแพลตฟอร์ม ⇒ ยอดจริง **33,210**
3. ต่ออายุ **ไม่ต้องกรอกเอกสารใหม่** แต่ยังต้องมีการตรวจฟาร์ม
4. คำขอใหม่ยังคงจ่าย 2 งวดตามเดิม
5. เลขค่าธรรมเนียมต้องไม่อยู่ในโค้ด application — เป็นข้อมูลที่มีช่วงวันที่บังคับใช้ (มีผลกับใบ 2)
6. อัตราที่ใช้กับคำขอหนึ่งใบ ผูกกับ **วันที่ยื่นคำขอ** (มีผลกับใบ 2)
