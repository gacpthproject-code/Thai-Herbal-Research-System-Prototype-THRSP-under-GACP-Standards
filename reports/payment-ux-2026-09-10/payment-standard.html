สิ่งที่ต้องเพิ่ม

ไม่ต้องรื้อทั้งระบบ · เพิ่ม สองสถานะ เข้าไปในตัวที่ตัดสินว่า “ยังเป็นหนี้อยู่ไหม” แล้วให้หน้าจอกับปุ่มอ่านจากตัวเดียวกัน

+ กำลังตรวจสอบการชำระเงิน + รายการหมดอายุ

นี่คือกฎเดียวกับที่ป้าย “ถึงกำหนดชำระตอนนี้” ที่เพิ่งทำเสร็จใช้อยู่ — ต่อยอดจากของเดิมได้เลย

กฎสี่ข้อที่ทุกระบบใช้เหมือนกัน

ข้อ 1 กับ 2 เป็นคำแนะนำที่ Stripe เขียนไว้ตรง ๆ ในเอกสารตัวเอง

1 · webhook เท่านั้นที่เขียนคำว่า “จ่ายแล้ว”

หน้าเว็บที่เด้งกลับมาหลังจ่าย ไม่ใช่หลักฐานการจ่าย เพราะผู้ใช้อาจปิดเบราว์เซอร์ หรือเน็ตหลุดก่อนกลับมาถึง · ระบบเราทำข้อนี้ถูกอยู่แล้วฝั่งหลังบ้าน แต่หน้าจอไม่ได้สะท้อนช่องว่างนี้

“You can’t rely on triggering fulfilment only from your checkout landing page, because it’s not guaranteed customers visit that page.” — Stripe

2 · ตัวรับเงินต้องทนถูกเรียกซ้ำ

webhook ถูกส่งซ้ำได้ และถูกส่งพร้อมกันสองครั้งได้ · ตัวจัดการต้องให้ผลเหมือนเดิมทุกครั้ง และต้องแยกให้ออกว่า “ส่งซ้ำ” ต่างจาก “เงินก้อนที่สอง” — จุดนี้คือบั๊ก C3 ที่เจอ

“Perform fulfilment only once per payment … your function might be called multiple times, possibly concurrently.” — Stripe

3 · หนึ่งงวด เปิดรายการจ่ายได้ทีละหนึ่ง

ตราบใดที่ยังมีรายการเปิดค้างอยู่ ปุ่มต้องไม่ให้สร้างใบใหม่ · ต้องพากลับไปที่ใบเดิม หรือบอกว่ากำลังตรวจสอบอยู่ · ปัจจุบันเรากดสร้างใหม่ได้ไม่จำกัด

4 · ทุกรายการต้องมีวันหมดอายุ

QR ที่ค้างข้ามวันคือ QR ที่ยังเรียกเก็บเงินได้ · ถ้าไม่มีวันหมดอายุ ใบเก่ากับใบใหม่ จะเรียกเก็บได้พร้อมกัน — คือบั๊ก C4 · Stripe Checkout บังคับข้อนี้ให้เอง (ค่าเริ่มต้น 24 ชม. สูงสุด 24 ชม.)

ทางเลือกการต่อ Stripe

ตอนนี้หลังบ้านเราสร้าง PaymentIntent เองแบบดิบ ๆ แล้วส่ง clientSecret มาให้หน้าเว็บ — ซึ่งหน้าเว็บไม่มีใครใช้ต่อเลย · Stripe เองแนะนำให้เลิกใช้วิธีนี้: “Stripe recommends using the Checkout Sessions API … Don’t use the Payment Intent API unless the user explicitly asks, because it requires significantly more code.”

ลำดับงานที่เสนอ

  1. เอาปุ่มที่จ่ายไม่ได้ออกก่อน หรืออย่างน้อยอย่าให้มันสร้างหนี้

    วันนี้กดปุ่มแล้วระบบออกใบแจ้งหนี้ทันที ทั้งที่จ่ายต่อไม่ได้เลย — หนี้ใบนั้นเองคือสิ่งที่ทำให้ปุ่มขึ้นซ้ำ · ทำได้เร็วที่สุดและหยุดอาการที่คุณเจอได้ทันที

  2. ต่อ Stripe Checkout ให้จ่ายจบได้จริง

    หลังบ้านเปลี่ยนจากสร้าง PaymentIntent ดิบ เป็นสร้าง Checkout Session (ใส่ line item ค่าธรรมเนียมรัฐ + ค่าแพลตฟอร์ม + VAT ได้ตรง ๆ) แล้ว redirect · ตั้ง expires_at ทุกใบ

  3. เพิ่มสถานะ “กำลังตรวจสอบ” และ “หมดอายุ”

    ต่อยอดจากกฎที่เพิ่งทำเสร็จ (phase-due-state.ts) · ป้ายกับปุ่มอ่านจากตัวเดียวกันอยู่แล้ว จึงขัดกันไม่ได้

  4. ปิดสองบั๊กเงินที่ค้างอยู่

    เทียบ paymentIntent.id ก่อนตอบว่า “ส่งซ้ำ” (C3) และส่ง assertTransition: true กันคำขอที่ปิดไปแล้วฟื้นกลับมา (C7) · เป็น diff เล็กทั้งคู่ ผมเขียนให้ได้ทันทีที่สั่ง

  5. แยกกลุ่มตามคำขอ ไม่ใช่ตามงวดอย่างเดียว

    ผู้ยื่นที่มีหลายคำขอตอนนี้เห็นบิลกองรวมกัน และปุ่มอาจพาไปจ่ายผิดคำขอ (C5) · ต้องพิมพ์เลขที่คำขอจริงบนการ์ด ไม่ใช่ UUID
