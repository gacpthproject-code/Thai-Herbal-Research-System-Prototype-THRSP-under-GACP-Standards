## 1. สรุปสั้น

ชุด 24 rules วันนี้ **ครบตามรายการของ กทล.1 ส่วนที่ ๓ เกือบทั้งหมด** — สิ่งที่ operator รู้สึกว่า "ไม่พอ" จึงไม่ใช่รายการเอกสารขาด แต่เป็นสามอย่างที่ซ้อนกัน: **(ก) เงื่อนไขของกฎแคบกว่าความจริง** — คำขอต่ออายุ/ใบแทนไม่ถูกขอบัตรประชาชน ทะเบียนบ้าน หรือหลักฐานนิติบุคคลแม้แต่ใบเดียว และเจ้าหน้าที่กด "รับคำขอ" ใบแทนได้โดยไม่มีเอกสารบังคับสักช่อง พร้อมพิมพ์ผลตรวจว่า "ครบถ้วน" (`decideDocumentOutcome` กรอง `required===true` ที่ไม่มีเลย + `.every()` บน array ว่าง = true — `apps/backend/services/application-document-review-service.js:147-149`, `apps/backend/routes/api/provider/document-reviews.js:153-157`); **(ข) หนึ่งช่องบรรจุเอกสารหลายใบแต่เก็บได้ไฟล์เดียวและตัดสินได้คำเดียว** (`@@unique([applicationId, currentForSlot])` — `apps/backend/prisma/schema/application-document.prisma:82` · verdict ต่อ `(applicationId, slotId, round)` — `application-document-review.prisma:45`) ทำให้ "บัตร ปชช.+ทะเบียนบ้าน", "หนังสือจดทะเบียน+บัญชีรายชื่อสมาชิก", "หนังสือรับรอง+บัญชีรายชื่อกรรมการ" ที่ กทล.1 ให้ติ๊กแยก กลายเป็นหนึ่งคำตัดสินรวม; **(ค) เอกสารที่ระบบขอไปแล้วพิสูจน์ตัวตนไม่ได้** — เลขบัตรที่ผู้ยื่นพิมพ์ไม่เคยถูกเทียบกับบัญชี, ฟอร์ม กทล.1 ที่ระบบพิมพ์ออกมาเว้นว่างช่องเลขประจำตัวประชาชน/เลขทะเบียนนิติบุคคล/เลขทะเบียนวิสาหกิจ เพราะ wizard เขียน key คนละชื่อกับที่ template อ่าน (`step2-identity-config.ts:36-67` เขียน `idCard/presidentIdCard/companyName/taxId/communityRegistrationNo` แต่ `apps/backend/services/pdf/katorlor1-template-service.js:175,185-192` อ่าน `nationalId/organizationName/juristicRegistrationNumber/communityRegistrationNumber` — grep ทั้ง repo ไม่พบตัวแปลง) และเงื่อนไข "ออกให้ไม่เกิน 6 เดือน" ไม่มีใครตรวจ (`maxDocumentAgeMonths` มีคอลัมน์แต่ไม่มีใครอ่าน — `requirement-rule.prisma:72-77` · `ApplicationDocument` ไม่มีคอลัมน์ `issuedDate` เลย)

## 3. สิ่งที่ควรแยกออกจาก SOP_MANUAL / SECURITY_RESIDUE_PLAN

**หลักที่ใช้ตัดสิน (เสนอให้ operator รับเป็นกติกา):** *แยกช่องเมื่อ (ก) ฟอร์มของกรมตั้งชื่อเอกสารสองใบในบรรทัดเดียว หรือ (ข) เจ้าหน้าที่ต้องตัดสินสองเรื่องแยกกัน* — เพราะหนึ่ง slot เก็บได้หนึ่งไฟล์และตัดสินได้หนึ่งคำ

- **`sop_manual` — ไม่แยก แต่ต้องมี checklist หัวข้อในตัวมัน.** วันนี้มันดูดหกช่องเดิมเข้ามา (`sop_cultivation/harvest/storage/pest/processing` fold ที่ `packages/validation/src/upload-rules.js:377-380`) และคำอธิบายตัวเองครอบแค่ "เตรียมพื้นที่ ปลูก ดูแล เก็บเกี่ยว เก็บรักษา แปรรูป" (`document-slots.js:398`) ⇒ **ไม่ครอบ** IPM (4.2), ปุ๋ย (4.3), สุขอนามัยบุคลากร (9.1/9.2), การตามสอบ/รหัสล็อต (10.1/10.2), สุขาภิบาลและของเสีย (11.x) · comment ของ fold เองยอมรับว่าปัญหานี้ต้องไปจบที่ "per-slot review" (`upload-rules.js:372-374`) แต่ review เป็น**หนึ่ง verdict ต่อ slot** ⇒ จนท. ที่พบว่าขาดบท IPM ต้องตีกลับ SOP ทั้งเล่ม — **นี่คือคำบ่นของ operator ในรูปกลไก** · **เสนอ: กทล.1 สั่งให้แนบ SOP ใบเดียว จึงคง 1 slot ไว้ แล้วเพิ่ม "หัวข้อย่อยที่ จนท. ติ๊กได้" ใต้ slot เดียวกัน** (ต้องขยาย review model ให้รับ sub-item) — ทางเลือกนี้ไม่เพิ่มไฟล์ให้เกษตรกรและไม่เกิน ruling 1 · ส่วนบทที่มาตรฐานบังคับแต่ SOP ไม่ครอบ ให้ไปเป็น P18-P21 ตามมติกลุ่ม ค
- **`security_residue_plan` — แยกเป็นสองช่อง.** ฟอร์มบรรทัด A6 ตั้งชื่อสองวัตถุในบรรทัดเดียว: "มาตรการรักษาความปลอดภัย" กับ "วิธีนำส่วนของกัญชาที่เหลือไปใช้ประโยชน์" (**CITED** `facts.md:41`) — เป็นคนละคำถามที่ จนท. ต้องตัดสินคนละครั้ง (ความปลอดภัย = การเข้าถึงพื้นที่ · ส่วนที่เหลือ = การไม่รั่วไหลออกนอกระบบ) เสนอ `security_measures_plan` + `residue_utilisation_plan` — **ภาระเพิ่ม = แยกไฟล์ที่เขียนเองอยู่แล้วเป็นสองไฟล์**
- **`building_plan_photos` — ไม่แยก แต่ต้องรองรับหลายไฟล์ต่อช่อง.** มันคือ "แบบแปลน + ภาพนอก + ภาพใน" (สามใบ) และ `site_photos` คือ "สถานที่ปลูก + การเก็บเกี่ยว" — พวกนี้เป็นภาพหลายใบโดยธรรมชาติ การแยก slot จะทำให้ฟอร์มยาวโดยไม่จำเป็น **ทางแก้ที่ถูกคือปลดล็อก `@@unique([applicationId, currentForSlot])` ให้หลายไฟล์อยู่ในช่องเดียวได้** (งานใหญ่กว่า — จัดคิวหลัง P1-P6)

**ผลกระทบต่อ snapshot และคำขอที่ยื่นไปแล้ว:**
- คำขอที่ยื่นแล้วถูกตราด้วย `buildRequirementSnapshot` = `{stampedAt, ruleIds, slotIds}` ณ วันยื่น (`apps/backend/services/application-document-requirements.js:187-196`) — การยื่นซ้ำ/แก้ไขถูกตัดสินด้วยตราใบนั้น **ไม่ถูกกฎใหม่ย้อนหลัง**
- **⚠ อันตรายที่ต้องแก้พร้อมกัน:** ประตูตรวจของ จนท. เรียก `resolveApplicationRequirements(application, documentRows)` **โดยไม่ส่ง `at`** (`routes/api/provider/document-reviews.js:132`) ⇒ ตกลงไปที่ `at: new Date()` (`application-requirements-service.js:462`) **แปลว่ากฎใหม่จะทำให้คำขอที่อยู่ในคิวตรวจอยู่แล้วกลายเป็น "เอกสารไม่ครบ" ทันทีที่ seed** · ต้องเลือกอย่างใดอย่างหนึ่งก่อน apply: (ก) ส่ง `at: application.submittedAt` ที่ประตู จนท. (ตรงกับตราที่ใบนั้นถือ) หรือ (ข) ตั้ง `effectiveFrom` เป็นวันที่คิวปัจจุบันเคลียร์แล้ว
- **ร่างที่ยังไม่ยื่น (DRAFT) จะถูกขอเอกสารเพิ่มทันที** — ต้องมีข้อความแจ้งในระบบก่อนวันที่กฎมีผล
- ไฟล์ที่เคยอัปมาใต้ id เก่า (`house_reg`, `JUR_DIRECTOR_LIST`, `COM_TVC03`) จะ**ไม่**นับให้ช่องใหม่โดยอัตโนมัติ — ถ้าอยากให้นับ ต้องเพิ่ม alias group ใน `packages/validation/src/upload-rules.js` (`SLOT_ALIAS_GROUPS`, บรรทัด 254) พร้อมกับ slot ใหม่
