## S4 — นัดตรวจ

**เห็นอะไร (สิ่งที่ backend คืนจริง)**
- `GET /api/applications/my` คืน `audit:{ mode: app.formData?.auditMode, meetingUrl: app.formData?.meetingUrl, location: app.formData?.auditLocation, auditorId: app.auditorId }` และ `scheduledDate: app.scheduledDate` (`application-listing-handlers.js:111-112`).

**เห็นอะไร (สิ่งที่ farmer เห็นจริงบนจอ) — Finding F4 (สำคัญ)**
- ค้นทั้ง `apps/web-app/src/app/health/**` ด้วย `grep "scheduledDate|meetingUrl|auditLocation"` — **ไม่มีไฟล์ใน `health/` ใช้ field เหล่านี้เลย** (field พวกนี้ปรากฏเฉพาะใน `apps/web-app/src/app/provider/**` — coordinator, scheduler, calendar).
- สิ่งที่ farmer เห็นแทนคือ label คงที่ `ACTION_META.WAIT_SCHEDULE` = "รอนัดหมายลงพื้นที่ / Coordinator กำลังประสานวันนัดหมายประเมินหน้างาน" (`application-detail-page-config.ts:108-111`) — **ไม่มีวันที่ ไม่มีเวลา ไม่มี meetingUrl ไม่มีที่อยู่ ไม่มีชื่อผู้ตรวจ** แม้ backend จะมี field พร้อมส่งอยู่แล้ว.
- สรุป: API พร้อม, DB พร้อม (`Application.scheduledDate`, `formData.auditMode/meetingUrl/auditLocation`, `Application.auditorId`), **แต่ farmer-facing UI ไม่เคย consume มันเลยสักหน้า** — เกษตรกรต้องรอโทรศัพท์/ข้อความจาก coordinator แทนที่จะเห็นในแอป ทั้งที่ backend ทำงานพร้อมแล้ว.

**กดอะไรได้**
- ไม่มี action ฝั่ง farmer ใน S4 — เป็น step ที่ coordinator ฝ่ายเดียวเป็นคนกด (assign auditor + set schedule) ผ่าน `/provider/scheduler`, `/provider/calendar` (นอกสโคป role นี้).

**จุดไหนชี้ legacy**
- ไม่ใช่ legacy-slip แต่เป็น **dead-data finding**: query คืน field ที่ FE ทิ้งไว้เฉยๆ (candidate สำหรับ `dead-route`/`dup-source` ratchet แต่ CLAUDE.md §3.6 ระบุ `dead-route` ยัง `[DRAFT] ไม่มี counter อัตโนมัติ` — บันทึกไว้เป็น manual finding).

## S6 — ใบรับรอง + QR

**เห็นอะไร**
- `/health/certificates` → `api.get('/api/certificates/my')` (`apps/web-app/src/app/health/certificates/client-view.tsx:136`).
- Backend `GET /api/certificates/my` (`apps/backend/routes/api/certificates/certificates.js:114-174`) คืน `certificateNumber, farmId, siteName, plantType, issuedDate, expiryDate, status, qrCode:cert.qrData, farm:{...}` **และ `audit: null` เสมอ (hardcode, `certificates.js:159`)**.

**Finding F5**: FE type `CertAudit` คาดหวัง `{score, auditorName, lastAuditDate}` (`apps/web-app/src/app/health/certificates/client-view.tsx:45-49`) และมี render branch จริงที่ใช้ `cert.audit.lastAuditDate` (`client-view.tsx:374-376`) — **แต่ endpoint ที่หน้านี้เรียกจริง (`/api/certificates/my`) ไม่เคยส่ง audit object ที่มีค่า** (ตายตัวเป็น `null` ที่ `certificates.js:159`) → ช่อง "ผลตรวจล่าสุด/ผู้ตรวจ" บนการ์ดใบรับรองจะไม่แสดงผลทุกกรณี แม้ backend มี audit record จริงในฐานข้อมูล (คนละ endpoint คนละ query ไม่ได้ join กัน).

**กดอะไรได้**
- Detail page `/health/certificates/[id]` → `GET /api/certificates/:id` (`certificates.js:216-223`), ownership ผ่าน `getCertificateForUser(certificateId, userId, ...)` → `prisma.certificate.findFirst({ where:{id, userId, isDeleted:false} })` (`apps/backend/services/certificate-service.js:786-793`).
- Download PDF: `GET /api/certificates/:id/download` (`certificates.js:280-330`) — ownership guard ซ้ำ (`getCertificateForUser` select เฉพาะ `id, certificateNumber`) + capability gate `PRINT_QR` (`:302-314`) ก่อนคืน PDF buffer ที่ฝัง QR.
- QR ที่แสดงบนจอ **generate ฝั่ง client จาก verify URL สด** ไม่ใช้ blob จาก backend โดยตรง (comment ยืนยันเหตุผล "may be stale after verify-base env var changes", `apps/web-app/src/app/health/certificates/[id]/client-view.tsx:19-22`, `102-122`) — fallback ไป `cert.qrCode` เฉพาะกรณี generate fail.

**อ้างข้อมูลชุดไหน**
- List: `prisma.certificate.findMany({ where:{userId, isDeleted:false}, include:{application:{select:{applicationNumber:true}}} })` (`certificate-service.js:767-778`) — tenant scope = `userId` (เจ้าของใบรับรองเอง ไม่ใช่ organizationId — ถูกต้องสำหรับ personal cert).
- Public verify (ไม่ auth, ใช้ตอน scan QR จริง): `GET /api/certificates/verify/:certificateNumber` (`certificates.js:336-374`) → `certificateService.findByCertificateNumber(certificateNumber)`, คืนเฉพาะ field สาธารณะ (`siteName, plantType, issuedDate, expiryDate, status`), ไม่มี PII.
- FE public page ที่ scan แล้วเจอ: `/verify/[cert-number]` (`apps/web-app/src/app/(public)/verify/[cert-number]/page.tsx`, `verify-view.tsx`).

**จุดไหนชี้ legacy**
- ไม่พบ URL/menu ที่ชี้ legacy slip ใน S6 (S6 ไม่เกี่ยวเงินแล้ว) — แต่ดู F5 ข้างบน (data-shape mismatch ไม่ใช่ legacy path แต่เป็น broken-contract).
