## 1. บันทึกอย่างไร

### สิ่งที่ **ทำงานจริงในระบบวันนี้**

เกษตรกรเปิด `/health/planting/new` แล้วกรอกฟอร์มที่มีช่องทั้งหมด **10 ช่อง** เท่านั้น:
ฟาร์ม · ใบรับรอง · ชนิดพืช · ชื่อรอบปลูก · วันเริ่มปลูก · วันคาดเก็บเกี่ยว · แหล่งที่มาพันธุ์พืช **(ถ้ามี)** ·
หมายเหตุ · พื้นที่ใช้งาน (ตร.ม.) ต่อแปลง · เป้าหมาย (ต้น) ต่อแปลง
(`apps/web-app/src/app/health/planting/new/client-view.tsx:332-443`)

**บังคับจริงฝั่ง server แค่ 4 ช่อง + แปลง 1 แปลง:** `if (!farmId || !plantSpeciesId || !cycleName || !startDate)` → 400
(`apps/backend/routes/api/cultivation/planting-cycles.js:194-199`) และต้องมี plotAssignments อย่างน้อย 1 (`:201-208`)
ช่องเดียวที่บังคับเพิ่มคือ `plannedPlantCount > 0` (`apps/backend/services/planting-service.js:143`)
**ไม่มีไฟล์ validator ของการปลูกเลย** — `apps/backend/validation/` มีแค่ไฟล์ของใบคำขอ 3 ไฟล์

**ช่องที่สเปกสั่งว่าบังคับ แต่ไม่มีที่ให้กรอกทั้งระบบ:** ตำบล/อำเภอ/จังหวัดของแปลง · พิกัด · สายพันธุ์ ·
วิธีปลูก/วัสดุปลูก · แหล่งน้ำ — grep คำเหล่านี้ทั้งโฟลเดอร์ `new/` ได้ศูนย์ผลลัพธ์
และประตูสร้างแปลงฝั่ง server ก็รับแค่ 4 ค่า: `{ name, area, areaUnit, solarSystem }`
(`apps/backend/routes/api/cultivation/plots.js:45`)

**พิสูจน์สด:** POST /api/planting-cycles ด้วย 4 ช่องบังคับ + 1 แปลง → **HTTP 201** และรอบปลูกที่มีอยู่เดิมในฐานข้อมูลจริง
(`12eb1e23-…`) คืนค่า `seedSource:null, soilType:null, irrigationType:null, varietyName:null`

### ข้อมูลไปอยู่ที่ไหน

| สิ่งที่บันทึก | โมเดล | ประตูเขียน |
|---|---|---|
| รอบปลูก | `PlantingCycle` (`prisma/schema/cultivation.prisma:5`) | POST /api/planting-cycles |
| บันทึกดูแล | `CultivationLog` — 6 ประเภท × 3 ขอบเขต (CYCLE/PLOT/PLANT_UNIT) | POST /:id/activities (`planting-cycles-activity-harvest-routes.js:34`) |
| ปุ๋ย/สาร | `FertilizerRecord` (`gacp-compliance.prisma:137-170`) — มี type ORGANIC/CHEMICAL/BIO, usageDate, withholdingDays, สูตร NPK ครบ | POST /api/fertilizer-records (`fertilizer-records.js:64`) |
| เก็บเกี่ยว | `HarvestBatch` (`harvest.prisma:8`) | POST /:id/harvest-batches และ POST /api/harvest-batches |
| บรรจุ | `Lot` (`trace.prisma`) | POST /api/lots |

**ข้อสังเกตที่สำคัญและยังไม่มีใครเขียนไว้:** `FertilizerRecord` มีทุกช่องที่หน้าสแกนสาธารณะตาม §4.4 ต้องใช้อยู่แล้ว —
ประเภทอินทรีย์/เคมี, วันที่ใช้, ระยะปลอดภัยก่อนเก็บเกี่ยว — และมี API ครบ mount แล้ว (`routes/api/index.js:300`)
**แต่หน้าจอการปลูกไม่เขียนลงตัวนี้** (มันเขียนลง PlantingActivity แทน) และ resolver สาธารณะไม่อ่านทั้งสองตัว
ทดสอบสด: GET /api/fertilizer-records/cycle/`fcc930b9-…` → 200 `{data: []}`
→ **ช่องว่างนี้เป็นเรื่อง "ต่อสายไม่ถึง" ไม่ใช่ "ยังไม่มีของ"** ซึ่งถูกกว่ามากในการปิด

### สิ่งที่ **ออกแบบไว้** (โน้ต)

สเปก §4.1 บรรทัด 48-51 สั่ง "บังคับครบทุกช่อง ไม่มี submit แบบขาด" พร้อม validator ฝั่ง server เท่ากับ FE
และสั่งให้ **เลิก** ดึงรายการฟาร์มจากฝั่งใบคำขอ — ทั้งสองข้อยังไม่ได้ทำ

## 2. ออก QR อย่างไร

### กลไกที่รันจริง

1. **ใครสร้างรหัส:** `qrcodeService.generateQRCodeId()` คือ `crypto.randomUUID()` เฉย ๆ
   (`apps/backend/services/qrcode/qrcode-service.js:100-102`)
2. **ผนึกลายเซ็น:** `registerTraceIntegrity()` แฮชสแนปช็อตของข้อมูล ต่อ hash chain แล้วเซ็น RSA-SHA256
   เก็บเป็นแถว `TraceQrSecurity` (`trace.prisma:67-101`) — มี `dataHash` / `previousHash` / `chainHash` /
   `signature` / `keyFingerprint`
3. **ใน QR มีอะไร:** **URL เปล่า ๆ อย่างเดียว** — `generatePublicTraceUrl` ต่อเป็น `<base>/trace/<path>`
   (`qrcode-service.js:124`) ไม่มีลายเซ็น ไม่มีข้อมูล ไม่มี token ที่ตรวจ offline ได้
   ลายเซ็นอยู่ฝั่ง server และถูกใช้เฉพาะตอน server แก้รหัสให้
4. **แก้ที่ไหน:** `/trace/plot-cycle/<uuid>` (QR แปลง) · `/trace/batch/<id>` · `/trace/lot/<id>` ·
   `/trace/<qrCode>` (ทางทั่วไป) · `/trace/plant/<code>` (รายต้น — ทิศทางที่ R8 เลิกแล้ว)
   ทุกเส้นเปิดสาธารณะ ไม่มี auth (`routes/api/trace/trace.js:64, :88, :127, :179`)

### ปัญหาที่พบตอนตรวจ

- **หนึ่งรหัส สอง URL:** `trackingUrl` ที่เก็บในฐานข้อมูลคือ `…/trace/plot-cycle/<qr>` แต่ endpoint ที่วาดรูป QR
  ฝัง `…/trace/<qr>` (`trace.js:132`) ทั้งคู่แก้ได้ แต่ **ตัวนับ scan ขยับคนละที่** ขึ้นกับว่าฉลากพิมพ์จาก URL ไหน
- **ลายเซ็นไม่ครอบข้อมูลที่คนสแกนเห็น:** `verifyTraceIntegrity` เอา payload ที่เก็บไว้มาแฮชเทียบกับ dataHash ที่เก็บไว้
  (`qrcode-service.js:490-498`) — ไม่เคยเทียบกับแถวปัจจุบัน ส่วน resolver อ่านสดจาก Prisma ทุกครั้ง
  **พิสูจน์สด:** QR แปลงถูกผนึกตอนรอบยังเป็น PLANTED ตอนนี้หน้าเดียวกันคืน `cycle.status:"HARVESTED"`
  คู่กับ `integrity:{valid:true, message:"QR code verified"}`
- **QR เก่าในฐานข้อมูลจริงชี้ไป `http://localhost`:** batch `LOT-2569-75C2-001` มี
  `trackingUrl: "http://localhost/trace/bf446ab6-…"` — ฉลากที่พิมพ์จากแถวนี้สแกนไม่ได้ตลอดไป
  (โค้ดไม่ผิด — ค่าถูกอบไว้ตอน mint ตอนที่ยังไม่ตั้ง base URL; ของที่ mint วันนี้ถูกต้องแล้ว)
- **โซ่แฮชข้ามผู้เช่า:** `getPreviousChainHash` เลือกแถว ACTIVE ล่าสุดของ entityType เดียวกัน
  **โดยไม่กรอง organizationId** (`qrcode-service.js:213-224`) → QR ของเกษตรกร A ต่อโซ่กับของเกษตรกร B
  และการ re-register เขียนทับ payload/signature เดิมในแถวเดิม → โซ่นี้ใช้เป็นหลักฐานการไม่ถูกแก้ไม่ได้
- **นับสแกนเพี้ยน 1:** ตรวจก่อนบวก (`:522` แล้ว `:559`) และ `scanCount || 1` (`common.js:145`) →
  QR ที่ไม่เคยถูกสแกนรายงานว่า 1 · `firstScan` / `lastScan` เป็น null เสมอ

### สิ่งที่ **ออกแบบไว้** (โน้ต)

§4.2 บรรทัด 57 สั่งให้ QR ทั้งสองใบผูก `certificateId` และ header หน้าสแกน "แสดงเลขใบ + ลิงก์ /verify/<เลขใบ>"
— หน้า QR แปลงไม่มีคำว่า certificate อยู่ในไฟล์ทั้งไฟล์ (ดูข้อ 4)

### สิ่งที่ **ออกแบบไว้** (โน้ต)

R10 (บรรทัด 122) เขียนคำต่อคำว่า **"QR มีสองใบเท่านั้น … ไม่มีใบที่สาม"**
ใบที่เกินมาแบ่งเป็นสองกลุ่มคนละเรื่อง และต้องแก้คนละแบบ:

- **QR รายต้น 10 ใบ** = ทิศทางที่ R8 เลิกถาวร แต่ยังเป็นค่าเริ่มต้นของทุกรอบใหม่ (ดูข้อ 5)
- **QR รุ่นเก็บเกี่ยว 1 ใบ** = **"ใบที่สาม" ที่ไม่มีใครออกแบบและไม่มีมติรองรับ** — ไม่มีกติกาบอกว่ามันชี้อะไร
  หรือแช่แข็งเมื่อไหร่ นี่คือช่องว่างเชิงออกแบบที่ต้องให้ operator ตัดสิน ไม่ใช่บั๊กที่ช่างซ่อมเองได้

## 4. Logic เป็นอย่างไร

### 4.1 ประตูใบรับรอง — มีจริง แต่มีที่เดียวครึ่ง

| ประตู | ตรวจใบรับรองหรือไม่ | หลักฐาน |
|---|---|---|
| สร้างรอบปลูก | **ตรวจจริง** (เจ้าของฟาร์ม + สถานะ active + ยังไม่หมดอายุ) | `planting-service.js:161-196` โยน `'Active certificate is required before creating planting cycle'` |
| เก็บเกี่ยวผ่านเส้นแปลง | **ตรวจจริง 3 ชั้น** (ไม่มี certificateId / ไม่ active / หมดอายุ) | `planting-cycle/harvest-capacity-operations.js:53-60` |
| POST /api/harvest-batches (สร้าง batch ตรง) | **ไม่ตรวจเลย** — grep คำว่า certificate ทั้งไฟล์ได้ศูนย์บรรทัด | `routes/api/cultivation/harvest-batches.js:218-315` |
| POST /api/lots (ออก QR สินค้า) | **ไม่ตรวจเลย** | `routes/api/trace/lots.js:64-186` |
| รีเฟรช QR แปลง | **ไม่ตรวจ** (แต่ idempotent — เซ็นรหัสเดิมซ้ำ ไม่ได้ mint ใบใหม่) | `planting-cycle-service.js:389-450` |
| เส้นอ่านอื่น ๆ (my, capacity, integrity) | **ไม่ตรวจ** แต่คืนขอบเขตว่าง | ทดสอบสดด้วยบัญชีไม่มีใบ → 200 ทุกเส้น, `count:0` |

**สามเรื่องที่ต้องพูดให้ตรง:**

- ฟังก์ชัน `verifyOwnedCycle` มีตัวเลือก `requireActiveCert` อยู่แล้ว (`planting-cycle-service.js:324`)
  แต่ **ไม่มีผู้เรียกคนใดส่งค่านี้เลย** — grep ทั้ง backend เจอแค่นิยามกับคอมเมนต์
- ประตูฝั่งหน้าจอ (`planting-cert-gate.tsx:38`) **จงใจ fail-open** — คอมเมนต์ในไฟล์เขียนเองว่า
  "presentation/honesty only, not the real security boundary" ทดสอบสดพบว่าเปิด `/health/planting/new`
  แล้วเห็นฟอร์มเต็มอยู่ราว 10 วินาทีก่อนหน้า lock จะขึ้น
- ประตูที่มีจริงกลับ **คืน HTTP 500 ไม่ใช่ 403** — DoD §6 บรรทัด 101 ระบุ "ไม่มีใบ = 403/หน้า lock"
- **สิ่งที่ยังเปิดอยู่แม้ไม่มีใบ:** สร้างฟาร์มและสร้างแปลงได้ (`farms.js:159-180`, `plots.js:37-58` ไม่ตรวจใบเลย)
  → "ทั้งเมนูล็อก" เป็นจริงเฉพาะกับปุ่มสร้างรอบปลูก ไม่ใช่กับโมเดลข้อมูล

**ข้อควรระวังในการอ่านผลนี้:** สเปก §4.1 บรรทัด 52 **จงใจอนุญาต** ให้บันทึกรอบเดิมต่อได้เมื่อใบหมดอายุกลางรอบ
ดังนั้นการที่เส้นอ่านไม่ 403 **ไม่ใช่การละเมิด R2 ในตัวมันเอง** ที่เป็นข้อบกพร่องจริงคือประตูหน้าจอ fail-open,
รหัสสถานะผิด, และสองประตูออก QR สินค้าที่ไม่ตรวจอะไรเลย

### 4.2 อะไรปลดล็อกอะไร

```
ใบรับรอง active ──► สร้างรอบปลูกได้ (ประตูจริงเพียงจุดเดียวของเลนนี้)
      │
      ▼
สร้างรอบปลูก ──► QR แปลง 1 ใบ (อัตโนมัติ) + QR รายต้น N ใบ (อัตโนมัติ ค่าเริ่มต้นเปิด)
      │
      ▼
**ต้องมีรายต้นก่อน** ──► ถึงจะเก็บเกี่ยวได้    ← harvest-capacity-operations.js:62 คืน 400
      │                                          "Plant units must be generated before harvest"
      ▼
เก็บเกี่ยว ──► HarvestBatch + QR + (ในธุรกรรมเดียวกัน) Lot + QR
```

ประตู "ต้องมีรายต้นก่อนเก็บเกี่ยว" คือ **การบังคับที่ระดับ server** ไม่ใช่แค่ข้อความบนหน้าจอ —
นี่คือเหตุผลว่าทำไม R8 ถึงยังไม่หายไป แม้จะมีการลบปุ่มบางส่วนออกไปแล้ว

### 4.3 หน้าสาธารณะแสดงอะไร ซ่อนอะไร

**ซ่อนถูกต้อง (ตรวจสดแล้ว):**

- ไม่มีพิกัดบน payload สาธารณะใด ๆ — สแกนหา latitude/longitude ทั้ง body ได้ false

  พิสูจน์สด: ตั้ง `harvestDate: '2029-05-05'` → 200 และหน้าสาธารณะพิมพ์ "5 พฤษภาคม 2572" หน้าตาเฉย

→ **ผลสอบ: ตก ทั้งสองทิศทาง**
(ก) ของที่เก็บก่อนได้ใบ (หรือหลังใบหมดอายุ) ยังโชว์ว่ารับรองแล้ว เพราะตรวจแค่สถานะวันนี้
(ข) พอใบที่เคยถูกต้องหมดอายุ ลอตเก่าทุกใบเริ่มคืน 410 Gone — หลักฐานของของที่อยู่ในโกดังผู้ซื้อหายไปพร้อมกัน
*(ข้อควรเป็นธรรม: เส้นเก็บเกี่ยวรายแปลงตรวจใบ ณ ขณะบันทึกจริง 3 ชั้น — สำหรับการเก็บเกี่ยววันเดียวกัน
นั่นคือการตรวจ ณ วันตัดโดยพฤตินัย ที่ขาดคือกรณีย้อนวัน กับเส้น POST /api/harvest-batches ที่ไม่ตรวจอะไรเลย)*

### สิ่งที่ระบบตอบได้จริงวันนี้ กับที่ตอบไม่ได้

| คำถามของผู้ซื้อ | ตอบได้ไหม |
|---|---|
| ลอตนี้มาจากฟาร์มไหน อำเภอ จังหวัดอะไร | **ได้** |
| ฟาร์มนี้ได้ใบรับรอง GACP ไหม | **ได้ บนหน้า batch/lot** — **ไม่ได้ บนหน้า QR แปลง** (ไม่มีเลขใบเลย) |
| ลอตนี้มาจากแปลงไหน | **บางส่วน** — ตอบได้เฉพาะ batch ที่สร้างผ่านเส้นแปลง และคำตอบมาจากการ **แกะสตริง JSON ออกจากช่อง notes** (`resolve-plot-cycle.js:208-215`) ไม่ใช่จาก foreign key · HarvestBatch ไม่มีคอลัมน์ plotId/cyclePlotId · PUT ทับ notes ครั้งเดียวสายนี้ขาด — พิสูจน์สดแล้วว่าหน้าแปลงเปลี่ยนเป็น "0 ชุดเก็บเกี่ยว / 0 ล็อต" ทันที |
| ใส่ปุ๋ย/สารอะไร เมื่อไหร่ ห่างวันตัดกี่วัน | **ไม่ได้** — ไม่มี resolver ไหนอ่าน FertilizerRecord หรือ CultivationLog เลย · ช่อง `withholdingDays` มีคนเขียนลง ไม่มีใครอ่านกลับ |
| ผลตรวจ Lab มีไหม | **ไม่ได้** บนหน้า QR แปลง และบนหน้าลอตเฉพาะทาง (ไม่มีคีย์ lab) |
| ถ้าผล Lab ออกมาไม่ผ่าน ต้องเรียกคืนถุงไหนบ้าง | **ไม่ได้** — ไม่มีโมเดล recall/withdrawal ไม่มีสถานะ HELD/RECALLED และ "ผู้ซื้อ" เป็นข้อความอิสระ (`Lot.destination`) |

**สรุปด้วยประโยคเดียว:** ระบบนี้ตามได้ว่า **ใครได้ใบรับรอง** และ **รหัสนี้เป็นของแปลง/ลอตไหน**
มันยังตามไม่ได้ว่า **เกิดอะไรขึ้นกับของชิ้นนี้** — ซึ่งคือสิ่งที่ §4.4 ถูกเขียนขึ้นมาเพื่อส่งมอบ
และประโยคที่ควรจำไว้: ลายเซ็นดิจิทัลพิสูจน์ว่าบันทึกไม่ถูกแก้หลังเซ็น มันไม่ได้พิสูจน์ว่าบันทึกนั้นเป็นความจริงตอนเขียน

## 7. ช่องว่างเรียงตามความสำคัญ

### ชั้น 1 — ปิดก่อนจึงจะพูดคำว่า Track & Trace ได้

**1. น้ำหนัก batch แก้ทีหลังได้ → เพดานสมดุลมวลยกได้ตามใจ**
ต้นทุน: ตัวคุมของนอกระบบเพียงตัวเดียวถูกปิดด้วย HTTP call เดียว ผู้ซื้อได้ถุงติด QR GACP ของของที่ไม่มีอยู่จริง
ปิดอย่างไร: ใส่ `freshWeight/dryWeight/lossWeight/harvestDate` เข้า `IMMUTABLE_BATCH_UPDATE_KEYS`
เมื่อ batch นั้นมีลอตแล้ว หรือบังคับให้การแก้น้ำหนักเป็น "รายการแก้ไขพร้อมเหตุผล" ไม่ใช่การเขียนทับ
(`harvest-service.js:15-22`) — **งานเล็กที่สุด ผลใหญ่ที่สุดในรายงานนี้**

**2. เนื้อหาหลัง QR ที่พิมพ์ไปแล้วยังเปลี่ยนได้ (R13)**
ต้นทุน: ถุงในโกดังผู้ซื้อมี QR ที่ผู้ขายเปลี่ยนเกรด สถานะ และวันเก็บเกี่ยวได้ทีหลัง — นี่คือกฎข้อเดียวที่แยก
Track & Trace ออกจากแผ่นพับโฆษณา
ปิดอย่างไร: มีสองประตู ต้องปิดทั้งคู่ — POST /:id/harvest (ตอนนี้กันแค่ `status === 'HARVESTED'`) และ
PUT /:id ที่ไม่กันอะไรเลย · แบบที่ถูกต้องมีอยู่แล้วในระบบ (`Lot.printedAt`) ยกขึ้นมาที่ HarvestBatch

**3. สร้าง HarvestBatch ได้โดยไม่มีรอบปลูก ไม่มีใบรับรอง ไม่มีแปลง — แล้ว QR มันบอกว่า valid**
ต้นทุน: ใครก็ตามที่ล็อกอิน health และมีฟาร์มหนึ่งแถว สร้างหน้า trace ตราสัญลักษณ์ GACP ให้ของที่ไม่มีที่มาได้
พิสูจน์สด: POST → 201 (`cycleId:null`), GET /api/trace/batch/… → 200 พร้อม `certificate:null` และ
`verification:{valid:true}` · สาเหตุ: `evaluateCertGate` คำนวณ `gated = !!cert && !isValid` — **ใบที่หายไปไม่ถูกกั้น
มีแต่ใบที่เสียเท่านั้นที่ถูกกั้น** (`common.js:246`)
ปิดอย่างไร: บังคับ certificateId ที่ประตู POST /api/harvest-batches และ POST /api/lots + แก้ให้ "ไม่มีใบ" = กั้น

**4. ไม่มี event log / edit history ที่ไหนเลย**
ต้นทุน: บันทึกใช้เป็นหลักฐานต่อผู้ตรวจ GACP ไม่ได้ ผู้ตรวจแยกไม่ออกระหว่าง "ปลูก 1 มี.ค." กับ
"วันที่ 30 พ.ค. อ้างว่าปลูก 1 มี.ค." · "event" ที่ระบบส่งออก (`interoperability-trace-events.js:47-100`)
คำนวณจากค่าปัจจุบันของแถวตอน request — แก้ `startDate` ประวัติเปลี่ยนตามเงียบ ๆ
รูปแบบเดียวที่มีคือ `PlantUnitEditHistory` ซึ่งอยู่กับโมเดลรายต้นที่เลิกแล้ว
ปิดอย่างไร: ตารางบันทึกการแก้ไขแบบ append-only สำหรับ PlantingCycle / HarvestBatch / FertilizerRecord
(§7.4 บรรทัด 143 สั่งไว้แล้ว)

### ชั้น 2 — ผู้ซื้อสแกนแล้วได้ข้อมูลผิด หรือไม่ได้ข้อมูล

**5. หน้า QR แปลงไม่มีใบรับรอง และไม่มีประตูตรวจใบ** — ใบถูกเพิกถอน หน้า batch/lot 410 แต่หน้าแปลงยังเขียว
ปิดอย่างไร: โหลด certificate เข้า `resolve-plot-cycle.js` + เรียก `evaluateCertGate` + เพิ่ม header เลขใบและลิงก์ verify
(หน้าอื่นทำแล้วทั้งหมด คัดลอกรูปแบบมาได้เลย) และเลิก hardcode `verification:{valid:true}` ทั้ง 4 จุด

**6. รายต้นยังเป็นค่าเริ่มต้น และเก็บเกี่ยวไม่ได้ถ้าไม่มี (R8)** — เกษตรกรทุกคนที่เปิดรอบวันนี้ถูกดันเข้าทิศทางที่เลิกแล้ว
โดยไม่รู้ตัว และได้ QR รายต้น 10-100 ใบที่ไม่มีใครอยากได้
ปิดอย่างไร: สวิตช์เป็น default off → ตัดเงื่อนไข `plantUnits > 0` ออกจากประตูเก็บเกี่ยว
(`harvest-capacity-operations.js:62`) → เอา `byStatus` รายหน่วยออกจาก payload สาธารณะ
**(ห้ามลบโมเดล — §5:96 สั่งไว้ว่าไม่ลบในงานนี้)**

**7. สายเชื่อมแปลง→batch เก็บเป็นสตริงในช่อง notes** — PUT ทับ notes ครั้งเดียว ที่มาของถุงหายถาวร
และไม่มี log ให้สร้างใหม่ได้ (พิสูจน์สดทั้งขาพังและขาซ่อม)
ปิดอย่างไร: เพิ่มคอลัมน์ `cyclePlotId` บน HarvestBatch (migration = Tier C) แล้วย้าย resolver ไปอ่าน FK

**8. หน้าสาธารณะไม่มี timeline / ไม่มีสรุปปุ๋ย-สาร** — คำถามสองข้อที่โรงงานถามจริงก่อนรับวัตถุดิบ
(ใส่อะไรลงไป และห่างวันตัดกี่วัน) ตอบจาก QR ไม่ได้
ปิดอย่างไร: **ถูกกว่าที่คิดมาก** — ข้อมูลและ API มีครบแล้ว (FertilizerRecord + CultivationLog)
ที่ขาดคือ (ก) หน้าจอการปลูกเขียนลง FertilizerRecord แทน PlantingActivity (ข) resolver อ่านมันขึ้นมาแสดง
**ไม่ต้องเปลี่ยน schema**

**9. R4/R5 ขาการ Lab ทั้งขา** — เกษตรกรวันนี้ไม่มีทางแนบผล Lab กับอะไรได้เลย และเมื่อแนบผ่านลอตได้
5 ลอตจากการเก็บเกี่ยวเดียวประกาศผลขัดกันได้
ปิดอย่างไร: โมเดล `BatchLabResult` ตาม §4.3 + หน้าอัปโหลด + ให้หน้าสาธารณะอ่าน existence จากตัวนี้
แทนที่จะอ่านจาก `cert.application.labResults` (ซึ่งเป็นข้อมูลจากใบคำขอ ไม่เกี่ยวกับของที่ถูกสแกน)

**10. R7 ไม่บังคับข้อมูลที่ทำให้ QR มีความหมาย** — QR ทุกใบวันนี้ชี้ไปที่รอบปลูกที่ไม่มีสายพันธุ์
ไม่มีแหล่งพันธุ์ ไม่มีวัสดุปลูก ไม่มีแหล่งน้ำได้
ปิดอย่างไร: เพิ่มช่องบนฟอร์ม + เขียน validator ฝั่ง server ให้เท่ากัน + ขยายประตูสร้างแปลง (`plots.js:45`)
ให้รับ ตำบล/อำเภอ/จังหวัด/พิกัด/วัสดุปลูก/แหล่งน้ำ

### ชั้น 3 — ความเป็นส่วนตัวและความถูกต้องเชิงระบบ

**11. เส้นสาธารณะเทข้อมูลเกิน + เดินไล่รหัสได้ + ไม่มี rate limit** — สแกน QR ถุงกัญชาแล้วได้รายการมาตรการ
รักษาความปลอดภัยที่ไซต์ชนิดนั้นต้องมี พร้อมชื่อฟาร์ม อำเภอ จังหวัด
ปิดอย่างไร: ตัด PlantSpecies ให้เหลือชื่อ/รหัสพืช, mask ชื่อฟาร์ม (โค้ด mask มีอยู่แล้วแต่ส่ง `name` เต็มมาคู่กัน),
ใส่ rate limit เฉพาะเส้น trace (`server.js:229-236` มีตัวเดียวทั้งระบบ 1000/15 นาที) — §4.5 สั่งไว้แล้ว

**12. ประตูใบรับรองคืน 500 ไม่ใช่ 403** — client แยกไม่ออกระหว่าง "คุณต้องมีใบก่อน" กับ "ระบบล่ม"
และ error rate ฝั่ง monitoring อ่านเป็น outage
*หมายเหตุที่ควรรู้: คอมเมนต์ที่ `planting-cycle-service.js:213` บอกให้เรียก `requireActiveCertificate` —
**ฟังก์ชันนี้ไม่มีอยู่จริงในทั้ง repo** ส่วน `hasActiveCertificate` ที่มีจริง (`:275`) ไม่มีใครเรียก*

**13. R11/R14 — สแกนแล้วอัพเดตไม่มีทั้งหน้าจอและ route** ทั้งที่นี่คือเหตุผลทั้งหมดของ QR ใบที่ 1
ต้นทุน: บนมือถือกลางแปลง เกษตรกรที่ล็อกอินแล้วสแกนป้ายของตัวเอง ได้หน้า public เหมือนคนแปลกหน้า
ปิดอย่างไร: หน้า `/trace/plot-cycle/[qr-code]` อ่าน session — ถ้าเป็นเจ้าของ แสดงปุ่มไปหน้าอัพเดต
(backend ส่ง `links` มาให้แล้ว หน้าจอทิ้งไว้เฉย ๆ ที่บรรทัด 83-85) · สิทธิ์ต้องมาจาก session ไม่ใช่จากรหัสใน QR

**14. QR ใบที่ 1 ผูกกับ (รอบ × แปลง) ไม่ใช่ผูกกับแปลง** — `buildPlotCycleEntityId` คืน `cyclePlot.id`
(`planting-cycle-service.js:103-105`) และ `@@unique([cycleId, plotId])` (`cultivation.prisma:107`)
→ ขึ้นฤดูใหม่บนแปลงเดิม = แถวใหม่ = QR ใหม่
ต้นทุน: §7.2 สัญญาว่าเป็นป้ายถาวรปักหน้าแปลง ไม่ต้องพิมพ์ใหม่ทุกฤดู — โค้ดทำแบบนั้นไม่ได้บนคีย์ปัจจุบัน
**ควรถาม operator ก่อนมีใครสร้างอะไรต่อจากพฤติกรรมนี้:** จะแก้ให้ผูกกับ plotId แล้วชี้ไปรอบปัจจุบัน หรือแก้ §7.2

**15. ไม่มี recall / ไม่มีข้อมูลผู้ซื้อแบบมีโครงสร้าง** — ผล Lab ออกทีหลังว่าไม่ผ่าน แพลตฟอร์มตอบได้แค่ว่า
"โทรหาเขาเอง" · ปิดโดย: สถานะลอต HELD/RECALLED + ตารางผู้รับ (งานเล็ก ควรตั้งเป็นหนี้ที่มีวันที่ ไม่ใช่ปล่อยลืม)

**16. แถวเก่าในฐานข้อมูลจริงที่ชี้ `http://localhost`** — ฉลากที่พิมพ์จากแถวเหล่านั้นเป็นกระดาษตาย
ควรรัน count `trackingUrl LIKE 'http://localhost%'` ก่อนพิมพ์อะไรจำนวนมาก (ยังไม่ได้รัน — ต้องต่อ DB ตรง)

### โอกาสที่ยังไม่มีใครเขียนไว้ (ไม่ใช่ช่องว่าง แต่คุ้มที่สุด)

**ภ.ท.27/28 เป็นฟอร์ม JSON เปล่าที่ไม่เชื่อมกับข้อมูลที่แพลตฟอร์มถืออยู่แล้ว** —
`report-submissions.js:66-102` นิยาม PT27 (`sourceData` / `storageQuantity` / `storageLocation`)
แต่ `formData` ถูกเขียนดิบจาก request body (`:276, :328, :389`) และ grep คำว่า plantingCycle/harvestBatch/lot
ทั้งไฟล์ได้ศูนย์ · แพลตฟอร์มมีตัวเลขที่ฟอร์มถามครบอยู่แล้ว แล้วให้เกษตรกรพิมพ์ใหม่เอง
→ ถ้าร่างรายงานให้อัตโนมัติจากบันทึกการปลูก **นั่นคือเหตุผลที่ทำให้เกษตรกรอยากบันทึกให้ถูกต้อง**
ซึ่งเป็นสิ่งที่ระบบ Track & Trace ทุกระบบต้องมี
*ข้อควรระวัง: ผลทางกฎหมายของการไม่ยื่น (พักใบอนุญาต 30 วัน) มาจากแหล่งข่าวเดียวและ **ยังไม่ได้ตรวจกับ
ประกาศกระทรวง** — อย่าอ้างตัวเลขนี้จนกว่าจะเปิดตัวบทจริง เหตุผลเชิงวิศวกรรมข้างบนไม่ต้องพึ่งตัวเลขนี้*
