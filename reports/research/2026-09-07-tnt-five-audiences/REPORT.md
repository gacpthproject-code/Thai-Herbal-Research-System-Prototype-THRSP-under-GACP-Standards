# ขอบเขตข้อมูล T&T ต่อผู้ชม 5 ฝ่าย — สิ่งที่ระบบเก็บได้จริง vs สิ่งที่แต่ละฝ่ายต้องการ (2026-09-07)

คำสั่ง operator: *"วิจัย วิเคราะห์ แล้วคิดหลายๆ มุม … ว่าสิ่งที่เกษตรกรต้องใส่ ต้องเป็นอะไร
คนที่ต้องการเห็น เช่นลูกค้า โรงงานต้องการเห็นอะไร กรมการแพทย์แผนไทยฯ ต้องการเห็นอะไร
อย. อยากเห็นอะไร กระทรวงเกษตรต้องการเห็นอะไร ทั้งหมดนี้เกี่ยวข้องกับข้อกฎหมายทั้งนั้น"*

วิธีทำ: อ่าน schema จริงทุกตาราง (CultivationLog · HarvestBatch · PackagingLot ·
BatchLabResult · PlantingCycle · Plot) + ประตู API จริง + หน้าจอจริง แล้วเทียบกับสิ่งที่
GACP (WHO guidelines + มาตรฐานกรม), พ.ร.บ.สมุนไพร/ยาเสพติดฯ, และผู้ซื้อเชิงพาณิชย์ต้องใช้
ทุกแถวของตาราง "มี/ไม่มี" วัดจาก schema กับประตู ไม่ใช่จากความจำ

## 1. เกษตรกร — ต้องบันทึกอะไร (มุม GACP: บันทึกคือหลักฐานการปฏิบัติ)

| สิ่งที่ GACP ต้องการ | ระบบวันนี้ | หมายเหตุ |
|---|---|---|
| กิจกรรมรายวัน: น้ำ/ปุ๋ย/ศัตรูพืช/วัชพืช/ตรวจแปลง/เหตุผิดปกติ | **มี** (7 ชนิด + วันที่ + แปลง) | |
| **ชื่อสาร/ปุ๋ยที่ใช้** | มีคอลัมน์แต่เพิ่งเปิดถาม (แก้วันนี้ `04161fd2`) | จุดตายของการตอบ อย./ผู้ซื้อ |
| ปริมาณ + หน่วย + วิธีใส่ | มี (เพิ่มชุดตัวเลือกมาตรฐานวันนี้) | |
| สภาพอากาศ/อุณหภูมิ/ความชื้น | มี (temperature/humidity มีคอลัมน์ **แต่หน้าจอไม่ถาม**) | ช่องว่างเล็ก |
| ภาพหลักฐาน | มี (แนบไฟล์ได้) | |
| **ระยะปลอดภัยก่อนเก็บเกี่ยว (PHI) หลังพ่นสาร** | **ไม่มี** — ไม่มีคอลัมน์ ไม่มีการเตือน | ช่องว่างจริงข้อ 1 (ดู §6) |
| เมล็ด/ต้นพันธุ์: แหล่งที่มา | มี (seedSource ต่อรอบปลูก) | |
| เก็บเกี่ยว: วันที่ น้ำหนักสด/แห้ง วิธีอบแห้ง อุณหภูมิ ชั่วโมง เกรด | **มี ครบดีมาก** (HarvestBatch) | |
| การบรรจุ: ชนิดบรรจุภัณฑ์ จำนวน น้ำหนัก/หน่วย วันบรรจุ วันหมดอายุ | มี (PackagingLot) | |
| COA: ไฟล์ + ชื่อแล็บ + เลขรายงาน + วันที่ | มี (BatchLabResult · ผูกกับรุ่นตามมติ 2026-09-05) | ทางเข้าเพิ่งเปิดวันนี้ `21f6ec46` |
| **ผู้ปฏิบัติงานจริง** (ใครพ่น ใครเก็บ) | มีแค่ `recordedBy` (คนกดบันทึก) | พอสำหรับฟาร์มเล็ก · ฟาร์มจ้างแรงงานตอบไม่ได้ |

## 2. ลูกค้า/โรงงาน (ผู้ซื้อวัตถุดิบ) — สแกน QR ล็อตแล้วต้องตอบได้ว่า

| คำถามของผู้ซื้อ | หน้าสแกนวันนี้ตอบไหม |
|---|---|
| ของแท้ไหม ฟาร์มไหนผลิต | ตอบ (ชื่อฟาร์ม + ที่ตั้ง + สถานะ VERIFIED) |
| มีใบรับรอง GACP จริงและยังไม่หมดอายุ | ตอบ (เลขที่ + วันหมดอายุ + isValid · เพิกถอน = 410) |
| ผ่านแล็บไหม COA ดูได้ไหม | ตอบ (tested จริงตามข้อมูล + ไฟล์ COA + ชื่อแล็บ) |
| รุ่นไหน เก็บเกี่ยวเมื่อไร | ตอบ (batchNumber + harvestDate) |
| น้ำหนัก/ขนาดบรรจุ | ตอบ (packaging block) |
| **พืชอะไร สายพันธุ์อะไร** | **ประตูที่หน้าผู้ซื้อเรียกไม่ตีพิมพ์ plant เลย** — รอมติ (evidence/tnt-scope-2026-09-07) |
| ใช้สารเคมีอะไรระหว่างปลูก | ไม่ตอบโดยเจตนา (บันทึกภายใน) — ตำแหน่งที่ถูกคือให้ COA พูดแทน ✓ |

## 4. อย. (กำกับผลิตภัณฑ์สมุนไพร/กัญชา)

| ต้องการ | ระบบวันนี้ |
|---|---|
| สืบย้อน ล็อต → รุ่น → รอบปลูก → แปลง → ฟาร์ม ได้ทั้งเส้น | **มี** (FK ครบทั้งเชน) |
| สารที่ใช้ระหว่างปลูก (ยาฆ่าแมลง ฯลฯ) ต่อรุ่นที่มีปัญหา | เพิ่งเป็นไปได้วันนี้ (productName เปิดถามแล้ว) — แต่ข้อมูลเก่าว่าง |
| COA ต่อรุ่น + แล็บที่ตรวจ | มี |
| **การเรียกคืน (recall): หยุดล็อตที่มีปัญหาให้หน้าสแกนบอกผู้ถือถุง** | **ไม่มี** — ล็อตไม่มีสถานะ RECALLED และหน้าสแกนไม่มีทางประกาศ | ช่องว่างจริงข้อ 2 (§6) |
| ผู้กระจายสินค้ารับล็อตไปไหนต่อ | ไม่มีโดยขอบเขต (จบที่ประตูฟาร์ม) — ตรงกับ scope ที่ตกลงไว้ |

| ต้องการ | ระบบวันนี้ |
|---|---|
| พื้นที่ปลูกจริงต่อรอบ (ตร.ม./ไร่) ต่อจังหวัด | มี (allocatedAreaSqm + จังหวัดของฟาร์ม) |

## 6. ช่องว่างที่พบ เรียงตามความเสี่ยงกฎหมาย

1. **PHI (Pre-Harvest Interval) ไม่มีในระบบ** — GACP หัวใจคือ "พ่นสารแล้วห้ามเก็บเกี่ยวภายใน
   X วัน" · ระบบรู้ทั้งวันพ่น (CultivationLog PEST_CONTROL) และวันเก็บ (HarvestBatch.harvestDate)
   แต่**ไม่มีอะไรเทียบสองวันนี้กัน** — เก็บเกี่ยวถัดวันพ่นก็บันทึกผ่านเงียบ ๆ · ขั้นต่ำที่ควรมี:
   คำเตือนตอนบันทึกเก็บเกี่ยวเมื่อมี PEST_CONTROL ภายใน 14 วัน (ค่าเริ่มต้น ปรับได้ต่อสาร)
2. **ไม่มีกลไก recall** — `Lot.status` มีค่า CREATED/PACKAGED/TESTED/SHIPPED ไม่มี RECALLED ·
   ถ้าแล็บพบสารปนเปื้อนหลังกระจายของ ผู้ถือถุงที่สแกนจะยังเห็น "ใบรับรอง valid" · ต้องมี:
   สถานะ + ประตู staff สั่ง recall + หน้าสแกนประกาศชัดเจน (คนละเรื่องกับเพิกถอนใบรับรอง
   ซึ่งกว้างเกิน — recall เจาะรายล็อต/รายรุ่น)
3. **temperature/humidity มีคอลัมน์แต่หน้าจอไม่ถาม** — คลาส select-gap เดิม (เล็ก)
4. **ผู้ปฏิบัติงานจริงต่อกิจกรรม** — มีแต่คนกดบันทึก · ฟาร์มที่ใช้แรงงานหลายคนตอบผู้ตรวจไม่ได้
   ว่าใครพ่น (กลาง — เป็นเรื่องออกแบบ ต้องคุยกับ operator ว่าจะบังคับแค่ไหน)

## 7. สิ่งที่ตรวจแล้ว "ถูกต้องดีอยู่แล้ว" (ไม่ต้องแตะ)

- COA ผูกรุ่นไม่ผูกล็อต + ไม่มีช่องพิมพ์ค่าตัวเลขเอง (ไฟล์คือความจริงเดียว) — มติ 2026-09-05 ถูกหลักมาก
- เก็บเกี่ยว→อบแห้ง→บรรจุ เก็บละเอียดครบ (วิธีอบ อุณหภูมิ ชั่วโมง เกรด น้ำหนักสูญเสีย)
- การแช่แข็งข้อมูลที่ขึ้นหน้าสาธารณะแล้ว (FROZEN_ONCE_PACKED) + แก้ไม่ได้หลังพิมพ์ QR
- หน้าสแกนแยก "ไม่เคยตรวจแล็บ" ออกจาก "ตรวจแล้ว" และไม่เหมารวมระดับรุ่นกับระดับล็อต
