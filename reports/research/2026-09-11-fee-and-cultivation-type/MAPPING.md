> operator 2026-09-11: *"1 รูปแบบการปลูกแบบในร่ม ตัวเอกสารหรือข้อมูลในดาต้าเบสก็จะเป็นในร่ม
> (เท่านั้น) เพราะเลือกแค่ 1 แล้วจ่ายเงินก็จะเป็นราคา 1 คำขอ ไปจนถึงการออกใบก็เป็น 1 คำขอ
> ไปถึงการบันทึกการปลูกก็สร้างกิจกรรมได้แค่คำขอที่ขอมา"*

ทุกตัวเลขและทุกข้อความในเอกสารนี้ **เรียกจากโค้ดจริงบน main** 2026-09-11 ไม่ได้พิมพ์มือ

## 1. หลักเดียวที่ทุกอย่างอ้างถึง

**สิ่งที่ผู้ยื่นติ๊กในขั้นที่ 3 (`farmData.areaTypes`) คือคำประกาศเดียว** ที่ราคา เอกสาร
ใบรับรอง แปลง และรอบปลูก อ้างต่อกันมาทั้งสาย · ไม่มีจุดใดตีความใหม่ และไม่มีจุดใดเดาแทน

คำมีสามคำ ไม่มีมากกว่านี้ (operator 2026-09-11):

| ค่าในระบบ | คำไทยที่ผู้ยื่นเห็น | บนใบเสนอราคา/ใบเสร็จ |
|---|---|---|
| `OUTDOOR` | กลางแจ้ง | กลางแจ้ง |
| `GREENHOUSE` | โรงเรือน | โรงเรือน |
| `INDOOR` | อาคารระบบปิด | อาคารระบบปิด |

## 2. ตารางราคา — ที่มาของทุกตัวเลข

```
ต่อหนึ่งลักษณะพื้นที่:
  งวดที่ 1  ตรวจสอบเอกสาร          5,000 + 500 (แพลตฟอร์ม 10%) + 385 (VAT 7%)  = 5,885
  งวดที่ 2  ตรวจประเมินแปลง+ออกใบ  25,000 + 2,500               + 1,925        = 29,425
                                                                    รวม        = 35,310

ยอดของคำขอ = ผลบวกของทุกลักษณะที่ติ๊ก   (ไม่ใช่คูณ — เป็นการบวกทีละบรรทัด)
```

| ติ๊ก | บรรทัดในใบ | งวดที่ 1 | งวดที่ 2 | รวมทั้งคำขอ |
|---|---|---|---|---|
| อาคารระบบปิด | 1 | 5,885 | 29,425 | **35,310** |
| กลางแจ้ง + โรงเรือน | 2 | 11,770 | 58,850 | **70,620** |
| กลางแจ้ง + โรงเรือน + อาคารระบบปิด | 3 | 17,655 | 88,275 | **105,930** |
| ต่ออายุ (ครั้งเดียว ไม่ตรวจเอกสาร) | ตามจำนวนลักษณะ | — | — | **35,310 ต่อลักษณะ** |

**ราคาขึ้นกับจำนวน ไม่ใช่ว่าเป็นแบบไหน** — อัตราต่อลักษณะเท่ากันทั้งสาม (ตรึงด้วยเทส
`area-types-are-a-closed-vocabulary`) ⇒ ติ๊กในร่มอย่างเดียว = ติ๊กกลางแจ้งอย่างเดียว = 35,310

**ชื่อบรรทัดบนเอกสารมาจากคำที่ติ๊ก ไม่ใช่เลขลำดับ** — วัดจริง:
ติ๊ก `INDOOR` → บรรทัดเขียนว่า **"อาคารระบบปิด"** · ติ๊กสองแบบ → **"กลางแจ้ง"** และ **"โรงเรือน"**

## 4. ตารางแมปปิ้ง — ติ๊กหนึ่งครั้ง เดินไปถึงไหนบ้าง

ตัวอย่าง: **ติ๊ก "อาคารระบบปิด" อย่างเดียว**

| ขั้น | ระบบถืออะไร | ด่านที่บังคับให้ตรงกัน |
|---|---|---|
| ผู้ยื่นติ๊ก | `farmData.areaTypes = ['INDOOR']` | จอมีสามช่อง · ไม่ติ๊กเลยไปต่อไม่ได้ (`step3-site-land-config.ts`) |
| ประตูยื่น | รับเฉพาะสามคำ · คำแปลก/คำซ้ำ/ไม่ติ๊ก = ปฏิเสธพร้อมเหตุผลไทย | `canonical-application-validator.js` `AREA_TYPES` |
| คอลัมน์ในฐาน | `Application.areaType = 'INDOOR'` — **มาจากที่ติ๊ก ไม่ใช่ค่าเริ่มต้น** | `shared/application-scope.js` `areaTypeFromTicks` |
| ราคา | 1 ขอบเขต = 35,310 | `fee-service.collectUniqueCultivationMethods` (ไม่มีทางถอยที่เดาชื่อให้แล้ว) |
| ใบเสนอราคา | หนึ่งบรรทัด เขียนว่า "อาคารระบบปิด" | `quotation-line-items.js` `thaiLabelForMethod` |
| ราคาตามสัญญา | แช่แข็งตอนกดยอมรับ | `payment-service-phase-flow.js:134` |
| ใบ กทล.1 ที่ระบบพิมพ์ | สามช่อง ติ๊กช่องอาคารระบบปิดช่องเดียว | `katorlor1-template-service.js` `AREA_BOXES` |
| เอกสารที่ต้องยื่น | ชุดของอาคารระบบปิด (แบบแปลนอาคาร) ไม่ใช่ชุดของกลางแจ้ง | `application-requirements-service.js` → ทะเบียนกฎ |
| ใบรับรอง | **หนึ่งใบของอาคารระบบปิด** · อายุนับจากวันที่รูปแบบนี้ผ่าน | `certified-scope.js` `certifiedAreaTypes` (อ่านทุกใบที่ยังมีผลแล้วรวม) |
| การสร้างแปลง | สร้างแปลงกลางแจ้งไม่ได้ | `routes/api/cultivation/plots.js:80` `assertPlotWithinCertifiedScope` |
| การแก้ฟาร์ม | เปลี่ยน `cultivationMethod` ออกนอกขอบเขตไม่ได้ | `farm-service.js:277` `assertCultivationMethodUnlocked` |
| **การเปิดรอบปลูก** | เปิดรอบบนแปลงที่อยู่นอกขอบเขตไม่ได้ — รวมถึงแปลงที่สร้างไว้ **ก่อน** ได้ใบ | `planting-service.js:335` `checkPlotsAgainstCertifiedScope` |
| QR ของล็อตที่ขาย | ชี้กลับไปที่ใบรับรองที่ครอบคลุมการปลูกนั้นจริง | ต่อจากด่านบน — รอบที่เปิดไม่ได้ ก็ไม่มีล็อตให้ออก QR |

ด่านสุดท้ายเป็นด่านที่ปิดช่องจริง: แปลงที่เกิดก่อนใบรับรองไม่เคยผ่านด่านสร้างแปลง
ถ้าไม่มีด่านที่ `planting-service` ฟาร์มที่มีแปลงในร่มอยู่ก่อน แล้วได้ใบที่ครอบคลุม
เฉพาะกลางแจ้ง จะยังเปิดรอบบนแปลงในร่มได้ และ QR จะพาผู้ซื้อไปหน้าที่อ้างใบรับรองเกินขอบเขต

## 5. สามเส้นทาง เทียบกันทั้งสาย

| | เส้น A | เส้น B | เส้น C |
|---|---|---|---|
| ติ๊ก | อาคารระบบปิด | กลางแจ้ง + โรงเรือน | ครบสาม |
| จ่ายทั้งคำขอ | 35,310 | 70,620 | 105,930 |
| บรรทัดในใบเสนอราคา | 1 | 2 | 3 |
| เอกสารที่ถูกขอ | ชุดอาคารระบบปิด | ชุดกลางแจ้ง **และ** ชุดโรงเรือน | ทั้งสามชุด |
| **ใบรับรองที่ได้** | **1 ใบ** (อาคารระบบปิด) | **2 ใบ** คนละเลข คนละวันหมดอายุ | **3 ใบ** |
| ขอบเขตรวมของฟาร์ม | อาคารระบบปิด | กลางแจ้ง + โรงเรือน | ทั้งสาม |
| แปลงที่สร้างได้ | เฉพาะในอาคาร | กลางแจ้งหรือโรงเรือน | ทุกแบบ |
| รอบปลูกที่เปิดได้ | เฉพาะบนแปลงในอาคาร | เฉพาะสองแบบนั้น | ทุกแปลง |

**หนึ่งใบต่อหนึ่งรูปแบบการปลูก** (operator 2026-09-11) · ผ่านบางรูปแบบก็ออกใบเฉพาะที่ผ่าน
ได้ทันที ไม่ต้องรอรูปแบบที่ยังไม่ผ่าน · ⇒ ด่านขอบเขตอ่าน **ทุกใบที่ยังมีผล** ของฟาร์ม
แล้วรวมกัน ไม่ใช่ใบล่าสุดใบเดียว (`certified-scope` — แก้แล้ว `91ae7a56`)

เส้น B มีของที่เคยพลาดจริง: ทะเบียนกฎให้เอกสาร **คนละชุด** ต่อหนึ่งลักษณะ (ภาพถ่ายแปลง
ของกลางแจ้ง · แบบแปลนอาคารของโรงเรือน/อาคาร) เคยมีตรรกะที่ยุบสองติ๊กเหลือ "ข้อที่คุมเข้มที่สุด"
ก่อนถามทะเบียน ผลคือฟาร์มที่ติ๊กกลางแจ้ง+โรงเรือนถูกบอกว่าเอกสารครบ ทั้งที่ขาดภาพถ่ายแปลง

## 6. จุดที่ยังไม่แน่น (พูดตรง ๆ)

| # | เรื่อง | สภาพวันนี้ |
|---|---|---|
| 1 | `Application.areaType` เป็น NOT NULL | ร่างที่ยังไม่ติ๊กถือคำว่า `UNDECLARED` ซึ่งไม่ใช่คำในทะเบียน ⇒ ไม่มีใครอ่านเป็นคำประกาศได้ · ปลายทางที่ถูกคือคอลัมน์ nullable = migration แยกใบ |
| 2 | แมปคำไทยของลักษณะพื้นที่มีห้าชุด | ยุบเหลือชุดเดียวเป็นงานแยก · ใบนี้ทำได้แค่ไม่เพิ่มชุดที่หก |
| 3 | `totalAreaTypes` | schema บอกเองว่าปลดระวางแล้ว เก็บไว้เผื่อ rollback แต่ **ไม่มีโค้ดใดอ่าน** — เหตุผลที่เก็บจึงหมดอายุไปแล้ว |
| 4 | แปลงแรกในจอสร้างฟาร์ม | `farm-info-step.tsx` สร้าง "แปลงที่ 1" ด้วยคำว่า `OUTDOOR` ตายตัว — โรคเดียวกับ default เดิม ยังไม่แก้ในใบนี้ |
| 5 | คำขอเดิมสามใบในฐาน | ไม่มี `farmData.areaTypes` เลย (มีแต่คอลัมน์ค่าเดียว) ⇒ ยื่นใหม่ตามกติกาวันนี้ไม่ผ่าน · เป็นข้อมูลชุดทดสอบ ไม่มีเงินจริงติดอยู่ |
